# ADR-0003 门禁自举任务的临时写通道

- 状态：accepted
- 日期：2026-10-26
- 关联：ADR-0002（效力层级）、TASK-002 裁决 V-2

## 1. 上下文

TASK-002 要修复门禁自身的 4 个派生执行件（trio-guard.ts、pre-push 模板、
selftest、init-agent）+ 1 个共享模板（board.template.md）。这 5 个文件中
两类被门禁自保覆盖：`.omp/hooks/**` 与 `bin/**` 为 `deny *`，`templates/**`
fail-closed。任何角色都写不了——包括 ARCH。而 policy.txt 是 `deny *`，
只有无角色身份（用户）可改。

矛盾：门禁自保「被约束者不得改写约束」与「门禁自身的缺陷只能由角色分工
修复」正面冲突（BUG-002）。此为门禁自举悖论的第二个实例（第一个是
TASK-001 的发布自举，见 ADR-0001 → ADR-0002 豁免机制）。

约束：ADR-0002 已否决 maintainer 角色、禁止 agent 会话 `unset TRIO_ROLE`；
policy DSL 无 deny-例外、无到期语义，且给 DSL 加此能力需先改 guard /
pre-commit——要开门才能造钥匙（自举悖论）。

## 2. 候选方案

1. **任务级临时写通道**：窗口期内把目录级 `deny *` 降为角色级 deny
   （arch/qa），DEV 由 fail-closed + 精确单文件 allow 放行；注释块写死
   回收条件，用户在任务终验后落盘回收。—— 优点：角色分离保留、根信任
   不动、有留痕有回收；缺点：回收是人工步骤，窗口期 bash 实时拦截降级。
2. ARCH / 用户代施 5 个文件，DEV 只出补丁说明 —— 优点：零授权风险；
   缺点：契约 §8 推倒重写；diff 失去角色溯源，用户既实现又终验；
   用户成为实现瓶颈。
3. 永久 `allow dev` 门禁派生件 —— 优点：一次到位；缺点：被约束者获得
   永久门禁改写权，违反自保语义，一票否决。
4. 门禁 DSL 增加 task-scoped / 到期指令 —— 优点：机器强制回收；
   缺点：实现它需要先改 guard.ts 与 pre-commit，自举悖论，成本不成比例。

## 3. 决策

选定 **方案 1**。窗口语义（与 policy.txt 注释同步为真值源的一部分）：

1. **可豁免对象仅限派生执行件**：`.omp/hooks/**`、`bin/**`、
   `templates/pre-push`、`templates/board.template.md`。
2. **根信任永不豁免**：`.omp/trio/policy.txt`、`.git/hooks/pre-commit`
   （含模板与已部署件）维持 `deny *`，任何窗口不得触及。
3. **通道形态**：policy 注释块（`BEGIN/END TASK-xxx 临时写通道`）+
   精确单文件 `allow dev`（禁通配）+ 注释内写死回收条件与恢复原文。
4. **生效与审计**：diff 由用户以无角色身份落盘（唯一可写 policy 的身份）；
   触碰窗口文件的 commit 显式 pathspec，git 历史即审计；看板决策记录
   引用裁决编号；DEV 落盘 diff 后需重启会话（guard 进程内缓存 policy）。
5. **回收**：任务 `user_signed` 后用户整段删除通道并恢复 `deny *`，
   QA 按契约 AC-12 核验，回收动作记看板。

## 4. 被否决方案及否决理由

- 方案 2：TASK-001 代施是因为当时无 DEV 会话；TASK-002 有 DEV，代施
  破坏角色分离与 diff 溯源，且用户双重身份（实现+终验）失衡。
- 方案 3：永久门禁改写权违反自保语义，无需再论。
- 方案 4：自举悖论 + 成本不成比例；程序性回收（AC-12）已补机器缺口。

## 5. 后果

- 正面：门禁可自维护；三角色分工不破坏；根信任全程不可触，pre-commit
  权威层保证未授权文件进不了 git 历史。
- 负面：①窗口期 DEV 侧 bash 实时拦截对两棵树降级（落盘可、提交不可，
  与 ADR-0002「guard 尽力而为」一致）；②`init-agent.sh` 是部署件，
  后门面由 QA 测试 + 终验 diff 审查补偿；③回收依赖人工 + AC-12 硬核验。
- **推翻条件**：窗口期内发生任何越权写入或后门尝试 → 立即回收，改走
  方案 2（用户代施）；若此类任务常态化（≥ 3 次/季度）→ 重审方案 4，
  评估给 policy DSL 增加到期语义的成本。
