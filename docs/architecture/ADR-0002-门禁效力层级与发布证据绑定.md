# ADR-0002 门禁效力层级、自举豁免与发布证据绑定

- 状态：accepted
- 日期：2026-10-26
- 关联：ADR-0001（发布权与 push 管控）、TASK-002 裁决 V-1

## 上下文

ADR-0001 落地后，v0.2.0 发布复盘暴露 6 项缺口（BUG-001）。其中三项属
跨任务架构问题，不是单点实现错误：

1. **门禁效力层级未定义**：trio-guard 的 bash 拦截是文本匹配，可被
   `git add --pathspec-from-file` 等写法绕过；同时 fd 重定向（`2>&1`）
   被误判为写意图。读者无从判断「哪一层是权威」。
2. **自举豁免无正道**：维护/自举任务产不出 qa 报告，pre-push 的 dev 分支
   永远 exit 1，唯一出路是 `unset TRIO_ROLE`——恰好绕开刚建立的发布链，
   无角色、无报告、无审计。
3. **放行证据未绑定对象**：pre-push 取全仓库 mtime 最新的报告与看板，
   旧任务的全绿证据可放行新推送。
4. （顺带）**真值源未定义**：`profiles/` 与 `.omp/trio/` 双份 rules；
   本仓库发布元数据（版本号/变更记录）散落 README 散文与 tag。

## 候选方案

### 效力层级
1. **三层模型（guard 尽力而为 / pre-commit、pre-push 权威）** —— 优点：
   与既有架构同构，不追加机制；缺点：接受第一层可绕过，需在契约明示。
2. 把 bash 拦截做成完备命令解析 —— 优点：第一层不可绕过。缺点：
   shell 语义无法穷举，成本极高且必有漏网，假完备比明示不完备更危险。

### 自举豁免
1. **看板机器可读字段 + 决策记录留痕** —— 优点：复用 board 单一权威，
   pre-push 可机械校验，审计随版本历史走；缺点：board 格式需增字段。
2. 引入独立 maintainer 角色 —— 优点：语义直白。缺点：新角色 = 新信任
   层 + 新启动路径，为一个边缘场景引入整套机制，YAGNI。
3. 仅靠 `unset TRIO_ROLE` 逃生舱 —— 优点：零改动。缺点：无痕、无审计，
   正是本次复盘定性的问题本身。

### 证据绑定
1. **报告基线 commit 必须是待推提交的祖先 + 看板显式引用报告路径** ——
   优点：机械可判定，`git merge-base --is-ancestor` 即可；缺点：边界
   （孤儿提交、rebase 后基线丢失）需额外规则。
2. 绑定任务 ID 字符串匹配 —— 优点：实现简单。缺点：字符串可伪造、
   无法证明报告对应的实际代码状态。

## 决策

1. **三层效力模型**（候选 1）：
   - `trio-guard.ts`（进程内，写前）——**尽力而为**。目标：拦住明显的
     越权写与误操作，接受文本匹配不完备；实现必须消除**误伤**（只读
     命令、fd 重定向、内容字面量不得触发拦截）。
   - `pre-commit`（暂存区）——**权威**。暂存路径逐一过白名单，deny 优先
     fail-closed；`--pathspec-from-file` 等绕过第一层的写法在这里被兜住。
   - `pre-push`（对外）——**权威**。发布权 + 证据绑定，语义见下。
   契约与文档必须写明：「绕过 guard 不等于绕过门禁」。
2. **自举豁免走看板字段**（候选 1）：board.md 标识段新增机器可读字段
   `release_gate: strict | exempt(<reason>)`。`exempt` 仅允许用于
   维护/自举类任务（无 qa 报告可产出），且 MUST 在看板决策记录行引用
   裁决编号。pre-push 校验：dev + `exempt(...)` → 放行并在 stdout 输出
   审计行（含 reason）。`unset TRIO_ROLE` 保留为**用户本人**逃生舱；
   agent 会话（有 TRIO_ROLE 的）禁止使用。
3. **证据绑定到待推提交**（候选 1）：pre-push 的放行前置 a 改为——
   看板 `qa_report` 字段显式指向本次任务的报告文件；该报告「基线 commit」
   MUST 是待推 local_sha 的祖先（`git merge-base --is-ancestor`）。
   看板取用不再按 mtime，改为「本次推送 ref 对应任务目录的 board.md」
   （由 board 的 `qa_report` / 任务目录绑定；实现可先取报告所在目录的
   board.md）。
4. **真值源单一化**：
   - `profiles/*.rules.md` 是**唯一真值源**；`.omp/trio/*.rules.md` 是
     init 时的**生成副本**。测试 MUST 含相等断言，漂移即红。
   - 本仓库发布元数据：`CHANGELOG.md` 为变更记录真值源（必有）；
     版本号真值源 = git tag（README 散文不作数）。不引入
     `VERSION` / `package.json`（本仓库非包，YAGNI）。

## 被否决方案及否决理由

- 完备命令解析：假完备比明示不完备更危险，成本不成比例。
- maintainer 独立角色：为边缘场景引入整套角色机制；看板字段足以表达。
- 仅 `unset`：无审计，是缺口本身而非解法。
- 证据绑定任务 ID 字符串：可伪造、不证明代码状态。
- `VERSION`/`package.json`/发布脚本 `trio-release.sh`：P2 的 G-5 只要求
  真值源明确 + CHANGELOG 补齐；发布脚本属增强项，另行立项再议。

## 后果

- 正面：误伤消除后 agent 日常读写不再被拦；自举发布有正道且留痕；
  旧证据放行新推送的错误放行面关闭；rules 双份漂移由测试守护。
- 负面：board 增加字段后模板、校验器、文档需同步（一次性成本）；
  证据绑定的祖先判定在 rebase/孤儿提交场景需按 spec 边界规则处理。
- 推翻条件：发布改由 CI 承担（连同 ADR-0001 一并重审）；或 board
  不再是任务状态单一权威（引入独立状态存储）时，豁免机制随迁。
