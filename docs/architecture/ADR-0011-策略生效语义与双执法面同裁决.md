# ADR-0011 策略生效语义与双执法面同裁决

- 状态：accepted
- 日期：2026-10-28
- 关联：`ADR-0002`（门禁效力层级）、`ADR-0003`（临时写通道 §4.7 已注「guard 进程内缓存 policy」）、`docs/task/TASK-006-2026-10-28-策略生效语义/arch-20261028-2014-spec.md`（本决策的操作契约）

## 1. 上下文

`.omp/trio/policy.txt` 是判定语义的单一真值源（`ADR-0000` 列为稳定内核，改动需 ADR + 两层同步），但它只定义了**判定语义**（deny 优先、fail-closed），没定义**生效语义**——策略变更何时生效、谁保证执法件看到当前策略。两个执法面各自读取策略，语义漂移：

| 执法面 | 读取方式 | 策略缺失时 | 策略变更后 |
|---|---|---|---|
| guard（`.omp/hooks/pre/trio-guard.ts`） | 进程内快照，**首查后终身不失效** | fail-closed | **不生效**（旧快照继续执法） |
| pre-commit（`.git/hooks/pre-commit`） | 每次提交**现读** | 与 guard 可能相反 | 即时生效 |

实证事故（三点，取证 `下游 arch-20261028-1522-bug-1.md`；本仓同类 B-1 记于 TASK-005 board §4）：
1. **新增 allow 不生效** → 可用性误伤（合法写入被旧快照拒）。
2. **新增 deny 不生效** → 安全向 **fail-open**（本应禁止的写入被旧快照放行）——与整体 fail-closed 方向相反，是本决策的核心动机。
3. **拦截文案把旧快照冒充当前策略** → 取证失真：看不出「按哪份策略执法」。

`ADR-0003` §4.7 曾以「DEV 落盘 diff 后需重启会话（guard 进程内缓存 policy）」作为流程缓解，`arch-20261026-0536-spec.md` §7 / `verdict-2` 亦多处依赖「重启会话」。这是**靠纪律的权宜**，不是契约：谁保证重启、漏重启算谁的、文案如何证明用的哪份策略，均无约定。BUG-1 把它升级为必须成约的缺口。

## 2. 候选方案

1. **每次判定重读 + 单一共享判定函数**：`loadPolicy` 按 `mtimeMs`+`digest` 校验，变更即重读；guard 与 pre-commit 消费同一 `decide()`；缺失/不可解析 fail-closed 并明示；文案带快照标识。—— 一致性强、fail-closed、可取证；代价是每次判定多一次 stat+摘要。
2. **维持快照 + 强制重启流程**（现状）：靠「门禁变更后重启会话」纪律。—— 零代码改动；但纪律不可机检、漏重启即 fail-open，BUG-1 正是此因。
3. **TTL 缓存**：快照定期过期重读。—— 降低读频率；但 TTL 窗口内变更仍不生效，fail-open 窗口非零，且 TTL 数值无据可依。
4. **显式失效信号**：policy 写入触发 reload 事件。—— 精准；但需跨进程信号机制，hook/pre-commit 是独立进程与一次性 shell，信号面复杂、易漏。

## 3. 决策

选定 **方案 1**：每次判定按 `mtimeMs` + `digest` 校验快照、变更即重读；guard 与 pre-commit 消费**同一共享判定函数**；策略缺失 / 不可解析两侧一律 **fail-closed 并明示原因**；拦截文案**附快照标识**，检测到旧快照时明示「按旧快照执法」。理由：唯一同时消除「allow 不生效」「deny 不生效（fail-open）」「文案取证失真」三症的方案，且把一致性从纪律升级为可机检契约（AC-6 双面同裁决断言）。

配套：非法行**整份策略失效**（不静默跳过）——静默跳过会吞掉 deny 行，制造 fail-open（见 spec §6）；策略写方须原子落盘（临时文件 + rename），避免读到半截策略。

## 4. 否决方案及理由

- **方案 2（快照 + 重启纪律）**：BUG-1 三点事故的直接根因；「重启」不可机检、无责任归属，文案仍无法证明用的哪份策略。靠纪律违背 `ADR-0002`「机械门禁优先于纪律」。
- **方案 3（TTL）**：TTL 窗口内 `deny` 变更不生效 = 非零 fail-open 窗口，安全性弱于方案 1；且 `deny` 的安全性本就要求「写前即刻」，任何延迟窗口都不可接受。
- **方案 4（显式失效信号）**：hook（进程内）与 pre-commit（一次性 shell）生命周期异构，信号/重载机制复杂且漏配即退化为方案 2 的隐患；成本高于方案 1 的每次校验。

## 5. 后果

- **正面**：策略变更下一判定即生效（含 `deny` fail-open 消除）；guard 与 pre-commit 同裁决可机检（AC-6）；文案带快照标识，取证可证明执法依据；「重启会话」从硬前置降为可选优化。
- **负面 / 缓解**：
  - 每次判定多一次 stat + 摘要 → 缓解：预算 < 5ms（p95，spec §5），策略文件极小，成本可忽略。
  - 非法行整份失效可能比「跳过坏行」更严 → 缓解：这是**安全向**的保守，且文案明示原因；策略文件由门禁自保 `deny *` 守护，非法行本不应出现。
  - 两执法面改用共享函数需动 guard 与 pre-commit（均在门禁自保 `deny *` 面）→ 缓解：走 `ADR-0003` 临时写通道由用户授权 + ARCH 代施，或用户无角色身份落盘。
- **推翻条件**（满足其一须重审本决策）：
  1. 出现**远程 / 多源策略**（不再单文件），`mtime`+`digest` 校验模型不适用。
  2. 实测证明「每次校验」的判定延迟超出预算且无法用更轻摘要缓解。
  3. 执法面数量增至三个以上且生命周期各异，共享判定函数抽象成本高于收益。
  4. 证明「fail-open 窗口可接受」的新安全模型（当前安全立场：`deny` 生效零延迟窗口）。

## 6. 合规备注

- 本决策只改「生效时机 + 双面一致性」，**不改** policy DSL 语法与 deny 优先判定语义（承 `policy.txt`、`ADR-0002`）。
- 落地实现触及 `.omp/hooks/**` / `bin/**` / `templates/pre-commit` 时，因门禁自保 `deny *`，须按 `ADR-0003` 走临时写通道或用户落盘，非 ARCH/DEV 可直改。
