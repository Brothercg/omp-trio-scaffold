# ADR-0015 工装安装布局映射与报告矩阵机检

- 状态：accepted（用户 2026-10-30 指令，TASK-009 立项）
- 日期：2026-10-30
- 关联：ADR-0003（门禁自举临时写通道）、ADR-0014（无角色执行窗口）、ADR-0006（下游对齐策略）、下游 `ADR-0003-trio-tooling-boundary`

## 1. 上下文

- 下游 `factor_synthesis` 已按自身 ADR-0003 把工装收拢到 `tooling/bin`、`tooling/tests`、`tooling/hooks`，
  而 `.git/hooks/` 只留安装产物；上游 `init-agent.sh` 仍按 `bin/**` + `tests/` 注入并直接覆盖
  `docs/REPLY-CONVENTIONS.md`（下游已分叉领先）。后果：下游 19 条回归断言 SKIP，夹具无法实跑。
- 上游报告模板已强制「AC → 用例覆盖矩阵」，但校验器 T1–T11 不检查该段：缺段 / 引用悬空 /
  SKIP 不成对仍可提交。下游 `C-13` 因此只有「模板硬则」，无机器约束。
- 约束：`.git/hooks/*` 为派生产物，hook 内 `VALIDATOR_REL="bin/trio-check-report.mjs"` 为硬编码；
  `policy.txt` 为根信任，任何角色的策略语义不得因本决策改变。

## 2. 候选方案

### 决策 A · 安装布局

1. **双份布局共存**（`bin/` 与 `tooling/bin/` 同时注入）——实现简单；双源漂移、下游目录边界形同虚设（否决）。
2. **上游统一改 `tooling`** ——上游自身与既有下游 `bin/` 布局同时断链（否决）。
3. **布局参数化**：`--layout auto|bin|tooling`（auto 按目标 `tooling/bin` 存在性判定）+ 显式覆盖；
   hook 产物按布局做一次 `bin/trio-` → `<TOOLS>/trio-` 替换；下游领先文件默认保留、`--force` 才覆盖。**选定**

### 决策 B · 报告矩阵机检

1. **保持模板硬则**（现状）——无机器约束，C-13 不闭环（否决）。
2. **语义级 AC 覆盖判定**（读 spec 对照 AC 全集）——需解析契约、误伤历史报告、判定不稳（否决）。
3. **结构级 T12**：矩阵段存在性 + AC 行编号合法/不重复 + 引用用例可解析 + SKIP 成对登记；
   不做 AC 全集对照。**选定**

## 3. 决策

- A 选定方案 3：`--layout` 参数化 + `--dry-run` 零写入预览 + 下游领先集合
  `{docs/REPLY-CONVENTIONS.md, .omp/trio/templates/board.template.md}` 默认保留。
- B 选定方案 3：新增 T12（规则 M1–M10，见 `arch-20261030-1539-spec.md` §2.5）。
  AC 行结论的机检口径：无结论列时按引用解析成立（被引用用例结论受 T4–T6 四值约束）。

## 4. 被否决方案及理由

- A1 双份共存：与下游目录边界（tooling 单一真值）直接冲突，且安装器每次运行都会制造第二份副本。
- A2 统一 tooling：上游自举与老下游立即断链，破坏向后兼容（bin 布局须继续可用）。
- B1 保持模板硬则：C-13 已判「模板硬则先行，校验器增量跟进」，本任务即该增量。
- B2 语义覆盖判定：校验器无契约输入，AC 全集不可得；强行实现会把契约分歧烧成测试红灯。

## 5. 后果

- 正面：同一安装器服务两种布局；下游 19 条 SKIP 具备实跑条件；缺矩阵报告在提交时即被拒。
- 负面 / 缓解：
  - 安装器逻辑复杂度上升（布局三分支 + 替换）→ 以 golden 目录夹具 + 幂等断言锁定（spec AC-1..AC-10）。
  - 报告提交门槛提高 → 模板已含矩阵段；T12 只拒「缺段 / 悬空引用 / SKIP 不成对」。
  - 历史报告不受影响：pre-commit 只校验暂存件，不回查归档。
- 推翻条件：出现第二种下游目录约定（第三种布局）→ 重新评估 `--layout` 是否改为配置驱动；
  T12 产生对合规报告的误伤 → 回退到模板硬则并重审规则集。
