# ADR-0005 任务命名、流程标记与接力提示词

- 状态：accepted
- 日期：2026-10-26
- 关联：ADR-0004（本 ADR 修订其 D5 的载体形态，其余不动）

## 1. 上下文

TASK-003 立项后用户补充三条需求（grill 9 问全对齐）：

1. `docs/task/` 目录名看不出 TASK 编号（编号只活在 board 字段里）。
2. 任务目录内要有「处置流程标记」——当前看不出「设计→开发→测试→迭代未完成项→
   直到全部完成」的流程位置与轮次。
3. 接力分配块要「完整提示词」：含任务承接方与详细指令，**直接复制过去就可用**；
   同时文件名也应能反映轮次。

现状缺口：目录名无编号；board 状态机/AC 表/交接备注四段分散，无流程链视图；
ADR-0004 D5 的三字段表（目标角色/修改指令/提示信息）要用户自己组装成提示词。

## 2. 候选方案

1. 命名：`TASK-<NNN>-<YYYY-MM-DD>-<slug>` / `<YYYY-MM-DD>-TASK-<NNN>-<slug>` / 去日期。
2. 回填：三个存量目录全改 / 只新任务用新格式 / 等 TASK-002 闭环再改。
3. 清扫：按所有者分三段 / 用户授权 ARCH 一次性代施 / 不清扫。
4. 流程标记：board 小节 / 独立 FLOW.md / 目录名动态阶段后缀 / 文件名阶段前缀。
5. 文件名：改 schema 加阶段段 / 自由段带轮次 / 不动。
6. 分配块：提示词块替代三字段表 / 并存 / 维持表。

## 3. 决策

### 3.1 N1 目录命名：`TASK-<NNN>-<YYYY-MM-DD>-<slug>`，存量全回填

编号首段（主键可见、`ls` 按号升序 == 时间序），日期保留（时间锚）。
存量三目录改名：

```
docs/task/TASK-001-2026-10-26-发布权与push管控/
docs/task/TASK-002-2026-10-26-发布门禁复盘/
docs/task/TASK-003-2026-10-26-回复规范落地/
```

- 否决日期首段：编号埋中段，痛点只解决一半。
- 否决只新任务用新格式：两套命名混排，认知负担反增。
- 否决等 TASK-002 闭环：无收益，TASK-003 产物先落旧名还得再扫。

改名 + 旧路径清扫由**用户授权 ARCH 一次性代施**（范围锁死：目录改名、旧路径
字符串替换、board 自引修正；不碰结论/断言/时间戳/状态值；单 commit 显式 pathspec
可 diff 审；hook 拦截时走未设 `TRIO_ROLE` 的人工逃生舱）。
否决按所有者分三段清：`git mv` 必然跨所有者暂存，三会话只为替换十几行字符串。

### 3.2 N2 文件名轮次：schema 不动，自由段带 `-第N轮`

- QA 报告：`qa-<YYYYMMDD>-<HHMM>-report-<主题>-第<N>轮.md`（T1 正则 topic 为 `.+`，
  直接放行；事实先例：`qa-20261026-1201-report-发布门禁复盘-第2轮.md`）。
- DEV 交付：`dev-<YYYYMMDD>-<HHMM>-release-第<N>轮.md`（policy glob `dev-*.md` 放行）。
- ARCH：spec 版本文内 `vN`、`verdict-N` 已编号，不动。
- 存量文件不改名，约定向前生效。

否决改 schema 加阶段段：T1 是机械门禁，改 schema 动校验器+模板+规则三处；
且**阶段是可变状态**，文件名应是不可变身份，跟状态改名重演断引用事故。

### 3.3 N3 处置流程段：board §2 内小节，4 阶段链 + 迭代日志

```markdown
### 处置流程

| 阶段 | 状态 | 轮次 |
|---|---|---|
| ① ARCH 设计（契约定稿） | done | spec v2 |
| ② DEV 开发 | 进行中 | 第 1 轮 |
| ③ QA 测试 | 待办 | — |
| ④ 闭环（user_signed + 挂起清单清零） | 待办 | — |

迭代日志：
- 第 1 轮 <时间>：<触发> → <去向>
```

规则：②⇄③ 回环即迭代（不设独立「迭代」阶段行）；状态值域
`done`/`进行中`/`待办`/`不适用`；**轮次口径 = 3 轮熔断定义**
（「QA 判未通过 → DEV 修 → QA 复测」计 1 轮），不另造口径；谁推进状态谁同轮
更新本段。未完成项内容不在此重复（归 AC 进度表/结论表）。

否决独立 FLOW.md：第二状态真值源必与 board 漂移（board 模板明文反对）。
否决目录名动态阶段后缀：每推进一步断一次引用。

### 3.4 N4 接力块形态：提示词块替代三字段表（修订 ADR-0004 D5）

分配块每个可执行步骤一段：

> **承接方：QA**
>
> ```text
> 【任务】TASK-00N-<slug> · <本轮目标>（第 N 轮）
> 【必读】<完整相对路径> —— <读它干嘛>
> 【指令】1. <动作> 2. …
> 【交付】<产物落位与命名>（轮次后缀按 N2）
> 【纪律】<红线>
> 【突出】必须重启窗口/会话才能执行下一步（无则删本段）
> 【完成】<做到什么算完> + <回写 board 哪一段>
> ```

- 七段骨架钉死；`【突出】` 仅在有重启/环境前置时出现（ADR-0004 D5-4 重启突出的落点）。
- **按需生成不预支**：只发当前可执行步骤的完整块，并行可执行才多块；后续步骤
  不预写（会失真），全局图景归 board 处置流程段。
- 触发时机沿用 ADR-0004 D5：状态 ≠ `user_signed` 或挂起清单非空 → MUST 以分配块
  结尾；真闭环写「任务闭环，无接力」；board 双写、board 为权威；`blocked`/
  `waiting_user` 承接方 = `用户`。

否决表+块并存：一处一义，两份必漂移。否决全链条预写：第 3 步提示词在第 1 步
落地时已失真，失真指令比没有指令更坏。

## 4. 后果

- 正面：`ls docs/task/` 一眼见编号与流程轮次；复制接力零组装成本；轮次口径全仓
  一致（文件名 = 身份，board = 状态）。
- 负面：改名一次性清扫成本（已授权代施）；提示词块比表格长（接受——省的是你的
  组装劳动）；board 每轮多维护处置流程段（一处三行，成本可控）。
- 推翻条件：
  1. 提示词块出现实际漂移/失真引发返工 → 重新评估是否给未来步骤加「草稿」标记。
  2. 任务量大到 `ls` 单屏放不下 → 重议目录分组（按状态/按月）。
  3. 轮次口径与熔断定义分叉（有人另起计数）→ 以熔断定义为准即时纠偏，不改 N2/N3。
