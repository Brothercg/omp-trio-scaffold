# ADR-0008 测试矩阵前移（测试内容由 ARCH 锁定在契约阶段）

- 状态：accepted
- 日期：2026-10-27
- 关联：ADR-0004（回复规范与 QA 报告口径）、ADR-0007（标题编号）
- 决策来源：用户拍板（2026-10-27，P3 采纳）

## 1. 上下文

用户提问：DEV 开发完成后应直接交 QA 测试，还是先由 ARCH 确定测试内容再交 QA。
约束：

- QA 的对抗性测试设计是其职责核心，不能降级成执行器；
- ARCH 是裁决者，若再审 QA 测试计划，「QA 质疑口径 → 裁决者 = 口径制定者」
  形成自审自裁循环；
- 串行等待要少（流畅最大化，ADR-0006 同源诉求）；
- 「必测什么」（契约点）与「怎么测穿」（对抗用例）是两件事，可分离归属。

## 2. 候选方案

1. **P1 现状**：spec AC = 必测内容，QA 自主设计用例 —— 优点：无新增等待；
   缺点：QA 漏测 AC 只能靠报告机检事后暴露。
2. **P2 DEV 后插 ARCH 审核点**：ARCH 审 QA 测试计划后开测 —— 优点：范围统一；
   缺点：多一跳串行；架空 QA 独立性；自审自裁循环。
3. **P3 测试矩阵前移**：ARCH 在 spec 阶段附「AC→断言映射」矩阵，QA 按矩阵
   全覆盖 + 自主加对抗用例 —— 优点：必测内容同样被 ARCH 锁定且发生在 DEV 之前
   （契约先行本义）；QA 独立性完整保留；缺点：spec 变长。

## 3. 决策

选定 **P3**，执行口径四条：

### 3.1 spec 增「测试矩阵」段（ARCH 职责）

每个 spec 的验收准则段之后附测试矩阵，每条 AC ≥1 行：

```text
| AC | 断言（测试可翻译的判定点） | 必测边界 | 归属 |
```

- 「必测边界」取自 spec 边界极值段；QA 的对抗用例**不预填**
  （N4 既定原则：按需生成不预支）；
- 格式细节见 `templates/spec.template.md` 的补丁（待用户落盘）。

### 3.2 QA 覆盖义务

- QA MUST 覆盖矩阵全部行，允许且鼓励追加对抗用例（追加行标注「对抗」）；
- 漏覆盖任一 AC = 验收报告不合规（总判不得为通过）。

### 3.3 机检兜底（后续任务落地）

- `bin/trio-check-report.mjs` 将增「AC 覆盖检查」：读 spec AC 清单，逐条要求
  报告含对应测试行；缺行即校验不过。落地前由 QA 报告自检清单 + 看板
  AC 进度表人工兜底；
- 该校验器属门禁自保 `deny *`，改动走 ADR-0003 写通道（用户人工落盘）。

### 3.4 流程位点

DEV 交付后**直接**交 QA，不设 ARCH 中间审核点；分歧仍走既有 contract-gap
裁决流程（verdict-N）。

## 4. 后果

- 正面：必测内容契约先行锁定；QA 独立性与对抗性完整保留；无新增串行等待；
  测试内容决策可审计（矩阵就在 spec 里）。
- 负面：spec 变长一节；机检落地前存在人工兜底窗口。
- 推翻条件：机检落地后 AC 漏覆盖仍高频发生 → 重审 P2（中间审核点）。
