# ADR-0012 威胁模型定位与执法面加固

- 状态：accepted
- 日期：2026-10-29
- 关联：`ADR-0001`（发布权与 push 管控）、`ADR-0011`（策略生效语义与双执法面同裁决，快照标识机制复用）、`docs/task/TASK-006-2026-10-28-策略生效语义/arch-20261028-2014-spec.md`
- 来源：2026-10-29 grill-me 全流程架构审计（Q1–Q12，拷问记录见当日会话；逐题裁决见 §3–§4）

## 1. 上下文

TRIO 门禁现状：进程内 hook（`.omp/hooks/pre/trio-guard.ts`，bash 写意图正则 AND deny glob）+ `pre-commit`（角色白名单复核）+ `pre-push`（DEV 发布门禁）。审计发现六处结构性缺口（§3）。用户定位：**个人使用脚手架，用户对交付质量终验担责，无对抗性多租户**。据此威胁模型收口（§2）：内容合谋类防护（恒真断言反作弊、状态机防伪）明确出栈；弱断言检测改以**质量门**身份保留（ADR-0013）。

## 2. 威胁模型（决策）

### 候选方案
1. **防呆不防恶**：门禁防误操作、防静默失效、防配置漂移；不防蓄意绕过，但绕过 MUST 机器可检出（留痕）。
2. **防恶**：对抗 agent 模型，全面机械强制（签名状态机、不可绕过层、内容质量校验）。
3. 混合按需。

### 决策
选定 **方案 1「防呆不防恶」**。理由：单人使用、用户终验担责；方案 2 的机械成本（Q4/Q5 手段）服务不到真实关切（落地结果质量），而质量杠杆另有承载（mutation 质量门，ADR-0013）。**被否决**：方案 2 —— 签名状态机、断言非平凡校验等对个人使用是纯开销（Q4/Q5 用户裁决不采纳）；方案 3 —— 按需混合无判别标准，等于逐案争论。

## 3. 执法面加固清单（逐题裁决）

### 3.1 逃生舱绕过可检出（Q1）
- 现状证据：`TRIO_ROLE` 未设即两道钩子全放行（guard 头注 L6、pre-commit 同）；`git commit --no-verify` / `git push --no-verify` 一键跳过，agent 与人零区别。
- **决策**：逃生舱保留（人工放行是合法设计），但绕过 **MUST 机器可检出**：pre-commit 写 marker；post-commit 核 marker 缺失即记 bypass 审计行；pre-push 展示审计行。
- 否决：禁用 `--no-verify`（git 原生能力，拦不住）；假定不会发生（违反防呆定位）。

### 3.2 写隔离对称化 + 落盘路径归一（Q2）
- 现状证据：write/edit 走 allow 白名单，bash 仅「写意图 AND deny glob」命中才拦（guard L784–791 只收集 `!rule.allow`）→ `python3 -c "open('src/x','w')"` 零 token 直接放行；全文件无 `realpath`/`lstat`（L231–236 纯词法 `path.resolve`）→ `ln -s src docs/task/x/l` 穿透。
- **决策**：bash 面对 allow 矩阵做与 write/edit 同语义判定；路径归一 MUST `realpath`，拒绝经 symlink 落盘。
- 否决：声明 bash 为可信通道 —— 违背「能力全开 + 物理隔离」核心承诺。

### 3.3 报告基线 == 待推代码（Q6）
- 现状证据：`check-report` 对基线只验 hex（L52–53, L165）；pre-push 只验「基线是待推 sha 的祖先」（注释 L11）——旧绿 commit 永远是新 tip 的祖先，测祖先推 tip 穿透。
- **决策**：报告基线 **MUST == 待推 `local_sha`**；或基线..local_sha 的 delta 仅含非代码路径白名单（如纯文档）才免复测，否则强制 QA 重跑。
- 否决：仅祖先校验（必要不充分，已证穿透）。

### 3.4 跨 worktree 写穿透封闭（Q10）
- 现状证据：policy 作用域条款「项目根以外绝对路径不受管辖」；guard `cachedRoot` 单根缓存（L727–728）；多 worktree 并存时 A 会话可写 B worktree 的 `src/`，两道钩子均不响。
- **决策**：**不支持跨 worktree 操作**：guard 检测到出根写入即拦 + 提示（防呆）。
- 否决：管辖 `git worktree list` 全 roots —— 复杂度高、单人场景收益低，列为推翻条件下的升级路径。

### 3.5 执法件版本自证（Q11）
- 现状证据：`trio-guard.ts`、`policy.txt` 是 worktree 内文件（随分支漂移），`.git/hooks/pre-commit|pre-push` 跨 worktree 共享；同仓两 worktree 可两套法；`init-agent.sh` 重装覆盖，不装则旧钩滞留。
- **决策**：执法件启动时 **MUST 自证版本**（自身版本 + policy digest 与 worktree 声明不符 → fail-closed + 明示，复用 ADR-0011 快照标识机制）；hooks 安装幂等且带版本指纹，漂移可检出。
- 否决：靠 `init-agent.sh` 重装纪律（无检出手段，漂移静默）。

### 3.6 身份断链不再静默（Q12）
- 现状证据：`TRIO_ROLE` 由 `start-agent.sh` 导出；直启 omp / 新 pane 手开 shell / login shell 重置 → 身份缺失 → **静默全放行**。这是「防呆不防恶」下最常见的真实事故路径。
- **决策**：无 `TRIO_ROLE` 时写操作不再静默放行——**放行但每次强制醒目提示**（「无身份运行，门禁未生效」）；`trio-install.sh --check` 类启动自检纳入日常。
- 否决：降级拒绝待 `TRIO_ROLE=human` 明示（更强防呆，但与「人工放行是合法逃生舱」设计冲突，列为高保障场景升级选项）；维持静默（最大防呆事故路径）。

## 4. 后果

- **正面**：词法隔离升物理隔离（3.2）；测推一致（3.3）；多 worktree 穿透面封闭（3.4）；执法漂移可检出（3.5）；两条静默失效路径（3.1/3.6）变可见。
- **负面 / 缓解**：
  - bash 判定面变宽（allow 矩阵 + realpath）→ 拦截误报可能上升；缓解：文案明示命中规则，误报可改 policy 解除。
  - 基线 == 待推 sha 会提高 QA 复测频率（delta 有代码即重跑）→ 缓解：非代码路径白名单免复测。
  - 实现触及 `.omp/hooks/**`、`bin/**`、`.git/hooks/*`（policy `deny *` 门禁自保面）→ 走 ADR-0003 临时写通道或用户无角色身份落盘，非 ARCH/DEV 可直改。
- **推翻条件**：
  1. 威胁模型升级（开源发布 / 多租户 / 对抗性 agent）→ 本 ADR 全部重审，回看 Q4/Q5 被否决手段。
  2. 支持跨 worktree 并行操作成为需求 → 3.4 升级为全 roots 管辖。
  3. git hook 行为变化（如 `--no-verify` 语义扩展）→ 3.1 重设计。
