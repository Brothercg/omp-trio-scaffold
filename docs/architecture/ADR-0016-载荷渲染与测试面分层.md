# ADR-0016 载荷渲染与测试面分层

- 状态：accepted
- 日期：2026-10-30

## 上下文

tooling 布局（ADR-0015）落点搬到了 `tooling/{bin,tests,hooks}`，但安装**内容**仍是
bin 布局文本（`bin/trio-...` 引用遍布模板/简报/REPLY/hook 源副本），安装后**测试面**
（selftest 发现、套件根解析、模板校验）也仍按 bin 布局寻址。下游 `factor_synthesis`
重装后 T10 报「引用路径不存在：bin/trio-check-report.mjs」，selftest 16/10、66/1。
约束：模板同时是 agent 手抄的记录范本（内容不可被占位符污染）；测试是 QA 独占资产
（不可安装期改写）；自托管仓内存在遗留拷贝（根 `tests/`、根 `templates/` 的 hook 件），
重装不得倒灌；门禁自检须在两布局都可跑。

## 候选方案

1. **布局无关占位符 + 安装器渲染** —— 模板写 `${TRIO_BIN}/...`，安装时渲染。
   优点：单一真值。缺点：占位符进 agent 手抄文本；与 hook 现有渲染分叉成两套机制；
   源文件需双向渲染，bin 布局也得渲染。
2. **安装期幂等文本渲染（选定）** —— 复用 `create_hook` 的三步占位符 sed（保护已有
   `tooling/` 前缀、左边界替换），统一覆盖全部含载荷路径引用的落点；源文件保持自然文本。
   优点：机制已存在且幂等；源=人类可读真值；bin 布局零渲染零回退。缺点：路径 token
   依赖文本模式（已知，禁词断言兜底）。
3. **不渲染，测试/文档各自按布局改写** —— 缺点：每处文本都要布局感知，散落即回归
   （本缺陷家族根因），否决。

测试面分层候选：

1. **目录拆分**（`tests/scaffold/` 不部署）—— 缺点：selftest glob、部署 glob、存量路径全动；
   遗留旧拷贝仍在执行面，否决。
2. **部署清单/标记过滤部署** —— 缺点：清单漂移；stale 无标记拷贝照样执行，否决。
3. **套件自声明 `@trio-suite scaffold-only`（选定）** —— selftest 按标记跳过；
   部署照旧（重装即覆盖为带标记版）。缺点：标记靠约定——由本 ADR 与 spec 判据固定。
4. **单套自适应（辅助，选定）** —— 载荷路径经 `tests/_layout.mjs` 地标探测 + 候选解析，
   一套测试双布局运行；否决「安装期改写测试内容」（源与落点分叉，审计/对齐二次适配）。

## 决策

选定「安装期幂等渲染（方案 2）+ 套件标记分层（方案 3）+ 单套自适应（方案 4）」。
理由：全部复用/收敛既有机制，零占位符污染、零测试内容分叉、零遗留倒灌
（执行件源序布局优先，见 TASK-012 spec R3）。

## 后果

- 正面：tooling 布局安装面内容自洽（模板/简报/REPLY/hook 引用布局正确）；一套测试双布局
  运行；`--force` 重装幂等；selftest 在目标仓可全绿。
- 负面：渲染靠文本模式（`bin/trio-` token 约定），新载荷含新路径 token 时须进渲染面清单
  （spec R1 的落点表）；缓解：AC-1 禁词断言在测试面持续把关。
- 负面：`@trio-suite scaffold-only` 是软约定；缓解：selftest 输出可见（跳过行），QA 报告计账。
- 推翻条件：出现布局无关引用机制（如工具统一从 PATH 解析）使文本渲染无意义；
  或测试资产允许安装期生成（改写）时。
