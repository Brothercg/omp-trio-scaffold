# ADR-0009 门禁自保范围收窄：文档模板与门禁执行件分离

- 状态：accepted
- 日期：2026-10-27
- 关联：ADR-0002（效力层级与根信任）、ADR-0003（自举写通道）、ADR-0008（测试矩阵）
- 决策来源：用户指令（2026-10-27，模板类维护改由 ARCH 代执行）

## 1. 上下文

`templates/**` 当前整体 fail-closed（无 allow 规则），其中混着两类东西：

1. **文档模板**（`spec/board/report/bug/verdict/release.template.md`）——
   文档骨架，不是约束执行件；
2. **门禁执行件出厂源**（`templates/pre-commit`、`templates/pre-push`）——
   直接决定拦截行为。

后果：任何模板微调（如 ADR-0008 的测试矩阵段）都要用户人工落盘。
用户 2026-10-27 明确要求此类操作由 ARCH 代执行（「又不是很复杂」）。

## 2. 候选方案

1. 维持全量 deny —— 每次模板调整都要用户出手（用户已判过重）。
2. `templates/**` 整体放权 arch —— 门禁脚本出厂源落入被约束者之手，
   「被约束者不得改写约束」被破坏（否决）。
3. **分离**：仅文档模板给 `allow arch`；执行件保持 fail-closed。

## 3. 决策

选定 **方案 3**，policy.txt 变更（由用户一次性落盘，policy 本身永远根信任、
不因本决策放开）：

```text
# 在 "allow arch docs/architecture/**" 行后新增：
allow arch templates/*.template.md
```

效力边界：

- `templates/pre-commit`、`templates/pre-push` 保持 fail-closed（根信任不变）；
- ARCH 对文档模板的改动仍受 pre-commit 全量复核与 git 历史审计；
- 文档模板的约束力来源是 `bin/trio-check-report.mjs` 机检 + QA/用户验收，
  不是模板文本本身——模板可改，机检不可绕。

## 4. 后果

- 正面：文档模板维护由 ARCH 端到端执行（改 + 提交），用户不再介入；
  门禁执行件根信任边界不变。
- 负面：ARCH 可改 report/spec 模板措辞——漂移风险由机检兜底 +
  QA 报告「格式自检」段暴露。
- 推翻条件：出现模板被用于规避机检的实例 → 收回 `allow arch`，恢复人工落盘。
