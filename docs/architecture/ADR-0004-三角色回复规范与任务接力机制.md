# ADR-0004 三角色回复规范与任务接力机制

- 状态：accepted
- 日期：2026-10-26

## 上下文

用户提出四条回复体验需求：

1. 结论先行：结论 + 解释，尤其**未完成/失败项**必须解释原因（开发失败、测试失败）。
2. 结构化输出：多用表格；产物引用用**完整项目相对路径**（点击即达）。
3. 任务未闭环时，回复 MUST 含「下一步任务分配」（目标角色 + 修改指令 + 提示信息），
   三角色持续接力直到闭环。
4. 前置条件未成熟的操作（例：TASK-002 的 AC-12 通道回收核验，解除条件 =
   `user_signed`）需要收尾机制——用户提议「前置全部完成时集中补测」。

现状缺口（已核对代码库）：

- 聊天回复无统一格式约束；只有 `qa-*-report-*.md` 有机检格式（T1–T9）。
- 产物路径写法混杂，裸文件名（`board.md`）常见，用户需自己去项目路径下找。
- `board.md` 交接备注是自由文本，无结构化接力块；会话重启后回复消失，接力信息只活在看板散文里。
- SKIP 只记账（跳过原因/解除条件），**不保证解除后动作被执行**——AC-12 的补测命令
  目前只活在交接备注中，无指定执行者，会话一换即可能遗失。
- 三份 `profiles/*.rules.md` 与 `.omp/trio/*.rules.md` 逐字节成对（AC-7 相等断言），
  共享内容写进 rules 即 ×6 漂移；`policy.txt` 已有「单一真值源 + 多处消费」先例。

## 候选方案

1. **落点**：写进三份 rules（×6 重复）/ 新建单一共享文档 + rules 薄指针 / 只写 RUNBOOK。
2. **结论骨架**：强制结论表表头 / 自由行文 + 必含字段。
3. **失败解释字段**：三角色统一一套 / 各角色自定义。
4. **路径规范**：纯约定 / 全面机检 / 约定 + 已有校验器加一条轻量存在性检查。
5. **接力块**：回复尾 + board 双写 / 只进 board / 只在回复尾。
6. **挂起项**：维持纯 SKIP 记账 / 任务级 board 挂起清单 + 集中补测轮 / 新建全局队列。

## 决策

### D1 落点：单一共享文档 `docs/REPLY-CONVENTIONS.md`

回复规范（结论骨架 / 失败解释 / 路径规范 / 接力块格式）全部承载于
`docs/REPLY-CONVENTIONS.md`（**单一真值源**）；三份 `rules.md` 各加一行强制指针：

> 你的回复与产物引用 MUST 遵循 `docs/REPLY-CONVENTIONS.md`。

产物类字段同步补进对应模板（report / release / board / spec）。

- 否决「写进三份 rules」：一条规范改一次同步 6 个文件，G-3 病灶复发。
- 否决「只写 RUNBOOK」：RUNBOOK 面向用户，不是 agent 每次会话必读的行权 prompt。

### D2 结论骨架：强制「结论表」表头，先结论后细节

每份角色回复开头固定一张表，之后才是解释性行文：

| 字段 | 含义 |
|---|---|
| `结论` | 一句话：本步完成了什么 / 判定了什么 |
| `状态` | 看板态（`implementing` / `testing` / `qa_passed` / `blocked` / `waiting_user`…） |
| `未完成项` | 有则逐条列（含失败/挂起），无则写「无」 |
| `产物` | 本步产出的完整相对路径 |

排序约束：**先讲结论，再简要阐述细节**。5 秒定律：用户能从任一角色回复 5 秒内
读出「做完没有、卡在哪」。

- 否决自由行文 + 必含字段：字段在行文里没有固定位置，角色一发挥即漂移。

### D3 失败解释：三角色统一字段，与 QA 机检同词根

失败/未完成项逐条填（只管回复与非报告产物；`qa-*-report-*.md` 的 T1–T9 格式不动）：

| 字段 | 含义 |
|---|---|
| `条目` | 哪条 AC / 什么操作 |
| `期望 / 实际` | 沿用 QA 机检三件套前两件 |
| `复现` | 命令或最小步骤（DEV 贴失败测试名，QA 贴复现脚本路径） |
| `根因` | 已定位写结论；未定位写「未定位 + 当前假设」 |
| `解除条件/下一步` | 谁做什么能转绿（挂起项填解除条件，缺陷填修复责任方） |

- 否决各角色自定义：差异应出现在内容里，不该出现在字段名里。

### D4 路径规范：约定为主 + T10 轻量存在性检查

> 产物引用 MUST 写从项目根起的完整相对路径（`docs/task/<slug>/arch-...-verdict-4.md`），
> 禁止裸文件名、禁止 `~`/绝对路径、禁止省略号缩写。完整路径首次出现可点击，
> 后文可用短名指代。

机检增量：`bin/trio-check-report.mjs` 在 T1–T9 之上加
**T10：qa 报告中反引号包裹的 `docs/`、`src/`、`tests/`、`bin/` 路径必须真实存在**。
其余产物暂不机检；聊天回复天然只能靠 prompt 纪律（无 hook 可拦聊天文本）。

- 否决全面机检（所有产物 + 全路径格式）：收益边际递减，先约定，漂移再收紧。

### D5 接力块：回复尾 + board 双写，board 为权威

任务未闭环时，回复 MUST 以「下一步任务分配」表结尾，同轮同步进 `board.md`
交接备注（会话重启不丢）：

| 字段 | 含义 |
|---|---|
| `目标角色` | `DEV` / `QA` / `ARCH` / `用户` |
| `修改指令` | 要做什么：改哪个文件的哪类内容、跑什么、裁决什么 |
| `提示信息` | 前置条件、要先读的文件（完整相对路径）、已知坑 |

约束：

1. 状态 ≠ `user_signed` **或挂起清单非空**时 MUST 以该表结尾；真闭环才写
   「任务闭环，无接力」。
2. board 为权威，回复表是本轮快照；冲突以 board 为准。
3. `blocked` / `waiting_user` 态 `目标角色` = `用户`，提示信息写明待裁决点。
4. **重启突出**：目标角色因新版本发布 / 门禁代码与策略变更必须重启会话才能
   执行下一步时，MUST 在分配块中着重突出「**该角色必须重启窗口/会话才能执行
   下一步**」（教训来源：B-10 / V-4，旧会话驻留 guard 代码导致误拦误判）。

- 否决只进看板：用户要自己翻 board 手抄成提示词。
- 否决只在回复尾：会话重启后接力信息消失，下个角色无从知道轮到自己。

### D6 挂起项：任务级 board「挂起清单」+ 集中补测轮

现有 SKIP 记账升级为 `board.md` 结构化段（qa 报告 SKIP 行是数据源）：

| 字段 | 含义 |
|---|---|
| `条目` | AC 编号或操作名 |
| `解除条件` | 可判定的未来事实（如 `user_signed`、外部 mock 就位） |
| `触发者` | 条件成熟后谁负责跑补测（`QA` / `DEV` / `用户`） |
| `解除后动作` | 精确命令或步骤（如 `bun tests/trio-gate-contract.test.mjs`） |

规则：

1. 每轮回复合盘：未清零挂起项必须出现在结论表「未完成项」。
2. 解除条件成熟 → **集中补测轮**：触发者下一轮一次跑完所有已成熟项，
   结果进 qa 报告/看板；不逐项零敲碎打。
3. **闭环判定修正：`user_signed` + 挂起清单清零 = 真闭环**（与 D5-1 呼应）。

挂起清单落**任务级** board（`docs/task/<slug>/board.md`），不建全局 board——
跨任务视图用 `grep -rn "解除条件" docs/task/*/board.md`；board 模板明文反对
全局历史段，挂起项永远属于某个任务。

- 否决纯 SKIP 记账现状：AC-12 证明会漏——解除动作无指定执行者等于没有解除动作。
- 否决逐项即时补测：把一轮活拆成 N 轮，反复触发 D5-4 重启约束。
- 否决全局队列文件：与任务级 board 必然漂移，谁维护又起三方扯皮（YAGNI，
  真出现跨任务挂起项时再议）。

## 后果

- 正面：三角色回复版式恒定（5 秒定律）；失败解释同词根跨角色可读；接力信息
  双写持久化；挂起项从「散文」变「有触发者的待办」，AC-12 类操作不再靠记忆收尾。
- 负面：每份回复多两张表（结论表 + 分配块）的输出成本；board 每轮多一次同步
  （漂移风险以「board 为权威」消解）；T10 误报需容忍（路径被删后旧报告会红，
  视为「报告引用了不存在的产物」的正确提示）。
- 推翻条件：
  1. 回复中连续两次出现裸文件名 → D4 升级为 pre-commit 扫全部暂存 md。
  2. board 双写出现实际漂移且引发事故 → D5 降级为 board 单写 + 回复只给指针。
  3. 出现跨任务才能解除的挂起项 → 重议全局队列。

本 ADR 固化的是决策与理由，行为以活文档为准。
