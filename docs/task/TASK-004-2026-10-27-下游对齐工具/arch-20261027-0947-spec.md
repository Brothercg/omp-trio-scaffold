## 1. 任务目标

下游项目通过 `bin/trio-align.sh` 检测并迁移到标准布局，且满足 ADR-0006 §3.5
验收链：「init ≤2 条命令 + `trio-selftest --fast` 全绿 + `trio-align --check`
零差异 + `policy.txt` `cmp` 逐字节相等」——四条全部机器可判定。

## 2. 接口签名

```text
bin/trio-align.sh --check [<目标目录>]   -> exit 0(零差异) | exit 1(有差异,stdout 逐条列出) | exit 2(参数/环境错误)
bin/trio-align.sh           [<目标目录>] -> 默认 dry-run：stdout 打印将执行操作，工作树零变化，exit 0
bin/trio-align.sh --apply  [<目标目录>]  -> 显式执行迁移 + 核验报告，exit 0(完成) | exit 2(错误)
bin/trio-align.sh --map <from>:<to> ...  -> 可选，显式目录映射（覆盖固定别名表），可重复传
```

| 名称 | 类型 | 可空 | 说明 |
|---|---|---|---|
| `<目标目录>` | 路径 | 是 | 缺省 `$PWD`；MUST 是 git 仓库根（否则 exit 2） |
| `--check` | flag | 是 | 只检测不落盘；与 `--apply` 互斥（同时给 → exit 2） |
| `--apply` | flag | 是 | 显式执行；默认模式是 dry-run，无显式 `--apply` 绝不落盘 |
| `--map` | `from:to` | 是 | 相对目标目录的 POSIX 路径对；`from` MUST 存在、`to` MUST 不存在（否则 exit 2） |

**固定别名表**（`--map` 未命中时生效，两条同时命中 → `--map` 优先）：

| 别名（from） | 标准（to） |
|---|---|
| `lib/` | `src/` |
| `app/` | `src/` |
| `spec/` | `tests/` |
| `test/` | `tests/` |
| `doc/` | `docs/` |
| `arch/` | `docs/architecture/` |

**运行形态（verdict-1 V-2）**：`trio-align.sh` 只从脚手架仓调用
（`<脚手架仓>/bin/trio-align.sh [--check|--apply] <目标目录>`），**不随下游部署**
（`init-agent.sh` 不部署本脚本）；「上游 policy」= 脚本所在仓的
`.omp/trio/policy.txt`。下游运行该工具 = 从脚手架仓指向下游目录。

## 3. 输入 / 输出边界

### 3.1 输入

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| 目标目录结构 | fs | 四标准目录 `docs/task/`、`docs/architecture/`、`src/`、`tests/` | 检测维度 = 存在性 + 任务目录命名形态 `TASK-<NNN>-<YYYY-MM-DD>-<slug>` |
| `policy.txt` | 文件 | 位于目标 `.omp/trio/policy.txt` | 与脚手架上游版本 `cmp` 逐字节比对 |

### 3.2 输出

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| 差异清单 | stdout 行 | 每行 `差异类型 | from | to | 处置` | `--check` 与 dry-run 都输出；零差异时输出 `aligned` 一行 |
| 核验报告 | stdout 块 | `--apply` 后输出 | 复用 TASK-003 AC-10 口径：逐行 diff，路径字符串外零改动 |

### 3.3 错误与副作用

- 退出码：`0` 成功/对齐；`1` 仅 `--check` 有差异；`2` 参数非法、目录不存在、非 git 仓库、`--map` 非法、`--check --apply` 同给。
- 副作用：仅 `--apply` 有——`git mv` + 全仓引用清扫（文本替换旧路径字符串）。
- 幂等性：`--check`/dry-run 天然幂等；`--apply` 对已对齐目录重复执行 = 零操作退出 0（幂等）。

## 4. 验收准则（AC，Given-When-Then）

### AC-1 `--check` 对齐判定
- **Given** 目标项目已是标准布局且 policy 与上游逐字节相等
- **When** 运行 `trio-align.sh --check`
- **Then** 退出码 0，stdout 仅 `aligned` 一行

### AC-2 `--check` 差异检出
- **Given** 目标项目含 `lib/`（无 `src/`）且 `.omp/trio/policy.txt` 与上游不同
- **When** 运行 `trio-align.sh --check`
- **Then** 退出码 1；stdout 含两行差异（`lib/→src/` 映射行、policy diff 行）；工作树零变化

### AC-3 默认 dry-run 不落盘
- **Given** 任意目标项目
- **When** 运行 `trio-align.sh`（无 flag）
- **Then** stdout 打印将执行操作清单；`git status --porcelain` 输出与运行前逐字节一致；退出码 0

### AC-4 `--apply` 迁移与引用清扫（verdict-1 V-1 口径）
- **Given** 目标项目含目录差异（如 `lib/` 无 `src/`）且 `.omp/trio/policy.txt` 与上游**逐字节相等**
- **When** 运行 `trio-align.sh --apply`
- **Then** `git mv lib src` 已发生；全仓文本文件中 `lib/` 路径字符串替换为 `src/`；随后 `--check` 退出码 0（policy diff 不由 `--apply` 消除，见 AC-2 与人工同步约定）

### AC-5 `--apply` 核验报告零越界（verdict-1 V-1 口径）
- **Given** AC-4 场景执行完毕（含 policy 相等前置）
- **When** 审 `--apply` 前后的逐行 diff
- **Then** 路径字符串替换行之外零改动（无结论/断言/时间戳/状态值变更）；`policy.txt` 不在 `--apply` 写入范围（ADR-0006 §3.4，逃生舱痕迹保留）

### AC-6 升级分类覆盖（U1）
- **Given** 目标项目已安装旧版脚手架，其中 `policy.txt` 被用户改过（逃生舱痕迹）
- **When** 重跑 `init-agent.sh`
- **Then** 执行件（`.omp/hooks/**`、`bin/**`、`templates/**`）直接覆盖为新版；`policy.txt` 打印 diff 提示且**不覆盖**，退出码 0

### AC-7 回归测试
- **Given** 本任务交付
- **When** 运行 `bun tests/trio-align.test.mjs`
- **Then** AC-1..AC-5 各有 ≥1 条用例，全绿；重复运行结果一致（无网络/时钟依赖）

### AC-8 文档落地（ADR-0007 编号规范）
- **Given** 本任务交付
- **When** 读 `README.md`
- **Then** 含「下游适配」小节（编号延续既有层级），说明对齐三命令（`--check` / 默认 dry-run / `--apply`）与逃生舱标注要求

### AC-9 验收链自证
- **Given** 对脚手架本仓自身运行
- **When** 依次跑 `trio-align.sh --check`、`trio-selftest --fast`
- **Then** 前者退出码 0（自身即标准布局），后者全绿；policy 与上游 `cmp` 退出码 0

### 4.1 测试矩阵（ADR-0008：AC→断言映射，QA 必全覆盖）

| AC | 断言（测试可翻译的判定点） | 必测边界 | 归属 |
|---|---|---|---|
| AC-1 | 退出码 0 且 stdout 仅 `aligned` 一行 | 已对齐即幂等 | QA |
| AC-2 | 退出码 1；差异 ≥2 行（映射行 + policy diff 行）；`git status` 前后一致 | 半迁移报「需人工裁定」 | QA |
| AC-3 | `git status --porcelain` 输出与运行前逐字节一致 | 任意项目零写入 | QA |
| AC-4 | `git mv` 发生 + 引用替换完成 + 复跑 `--check` exit 0 | `--map` 优先于别名表；夹具 policy 相等（V-1） | QA |
| AC-5 | 前后 diff 仅路径字符串替换行 | 零越界（结论/断言/时间戳/状态值零变更） | QA |
| AC-6 | 执行件被覆盖、policy.txt 未被覆盖且打印 diff、exit 0 | 逃生舱痕迹保留 | QA |
| AC-7 | 套件全绿且重复运行一致 | 无网络/时钟/随机依赖 | QA |
| AC-8 | README 含「下游适配」小节与三命令说明 | 层级编号延续（ADR-0007） | QA |
| AC-9 | `--check` exit 0 + selftest 全绿 + `cmp` exit 0 | 本仓自证 | QA |

> QA 对抗用例不预填（按需生成不预支）；追加行在报告中标注「对抗」。

## 5. 边界极值

| 场景 | 输入 | 期望 |
|---|---|---|
| 空值 | 不给目标目录 | 用 `$PWD`；非 git 仓库 → exit 2 |
| 非法 | `--check --apply` 同给 | exit 2，报参数互斥 |
| 非法 | `--map` 的 `from` 不存在 / `to` 已存在 | exit 2，报映射非法 |
| 下限 | 目标已是标准布局 | `--check` exit 0；`--apply` 零操作 exit 0（幂等） |
| 重复 | `--apply` 连跑两次 | 第二次零操作 exit 0 |
| 冲突 | 别名表与 `--map` 同时命中 | `--map` 优先 |
| 半迁移 | `lib/` 已存在且 `src/` 也存在 | 不自动合并，报差异行「需人工裁定」（exit 1） |

## 6. 非功能约束

| 维度 | 要求 | 验证方式 |
|---|---|---|
| 安全性 | 非 `--apply` 路径 MUST 零写入 | AC-3 断言 `git status` 不变 |
| 幂等 | `--apply` 重复执行零副作用 | AC-5/边界「重复」行 |
| 可观测性 | 差异清单/核验报告逐行可读、含 from→to | AC-2/AC-4 输出断言 |
| 兼容性 | bash ≥ 4、git ≥ 2.x；不依赖 bun/node（迁移工具纯 bash） | 自测环境说明 |

## 7. 范围外

- 不做 D 双层 policy（M2 缓，ADR-0006 §3.1）；
- 不做 `--layout` 模板集（B 已否决，ADR-0006 §2）；
- 不迁 git 历史内旧路径（只清工作树现存文本）；
- 不动 `templates/**` 骨架编号（fail-closed，用户落盘）。
