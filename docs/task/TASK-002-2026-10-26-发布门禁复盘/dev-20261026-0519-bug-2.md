## 1. 缺陷现象

TASK-002 spec §8 把以下文件分配给 DEV 实现，但 `.omp/trio/policy.txt`
（写策略唯一真值源）对 DEV 的判定全部为拒绝。实现尚未开始即被写门禁拦截：

| 契约要求 DEV 改的文件 | AC | policy 判定 | 冲突原因 |
|---|---|---|---|
| `.omp/hooks/pre/trio-guard.ts` | AC-1/2/3 | `路径 ".omp/hooks/pre/trio-guard.ts" 命中禁止规则 (* .omp/hooks/**)` | 门禁自保 `deny *` |
| `templates/pre-push` | AC-4/5/6 | `路径 "templates/pre-push" 不在 [DEV / 开发] 的写入白名单内` | fail-closed，无 `allow dev templates/**` |
| `templates/board.template.md` | AC-10 | `路径 "templates/board.template.md" 不在 [DEV / 开发] 的写入白名单内` | 同上 |
| `bin/trio-selftest.sh` | AC-8 | `路径 "bin/trio-selftest.sh" 命中禁止规则 (* bin/**)` | 门禁自保 `deny *` |
| `bin/init-agent.sh` | AC-8 | `路径 "bin/init-agent.sh" 命中禁止规则 (* bin/**)` | 门禁自保 `deny *` |

- **实际行为**：DEV 身份下对上述 5 个文件的写操作全部被 `trio-guard` 以命中
  禁止规则 / 不在白名单拒绝；`decide()` 的返回见 §3。
- **期望行为**：spec §8 明确「全部由 DEV 做」，且未给出 `unset TRIO_ROLE`、
  maintainer 角色或其它替代通道；ADR-0002 还明确否决 maintainer 角色。
- **复现概率**：必现（纯函数判定，与模型、网络、时钟无关）。

> 注：AC-7 只需保证 `profiles/*.rules.md` 与 `.omp/trio/*.rules.md` 当前一致
>（已一致），不需要写文件；AC-9 的 CHANGELOG 由 ARCH 负责。受阻的是其余
> AC 的全部实现入口。

## 2. Failing Test Script

类型为 `contract-gap`，按 `templates/bug.template.md` §2，`tests/repro` 仅对
`type: code` 强制。本次不新增 `tests/**` 文件，直接用策略纯函数复现：

```bash
bun -e '
import { parsePolicy, decide } from "./.omp/hooks/pre/trio-guard.ts";
import * as fs from "node:fs";
const rules = parsePolicy(fs.readFileSync(".omp/trio/policy.txt", "utf8"));
for (const p of [
  ".omp/hooks/pre/trio-guard.ts",
  "templates/pre-push",
  "templates/board.template.md",
  "bin/trio-selftest.sh",
  "bin/init-agent.sh",
]) console.log(p, JSON.stringify(decide(rules, "dev", p)));
'
```

## 3. 复现堆栈

```
$ bun -e '...decide(rules,"dev",p)...'
.omp/hooks/pre/trio-guard.ts {"allowed":false,"reason":"路径 \".omp/hooks/pre/trio-guard.ts\" 命中禁止规则 (* .omp/hooks/**)"}
templates/pre-push {"allowed":false,"reason":"路径 \"templates/pre-push\" 不在 [DEV / 开发] 的写入白名单内"}
templates/board.template.md {"allowed":false,"reason":"路径 \"templates/board.template.md\" 不在 [DEV / 开发] 的写入白名单内"}
bin/trio-selftest.sh {"allowed":false,"reason":"路径 \"bin/trio-selftest.sh\" 命中禁止规则 (* bin/**)"}
bin/init-agent.sh {"allowed":false,"reason":"路径 \"bin/init-agent.sh\" 命中禁止规则 (* bin/**)"}
```

策略原文（`.omp/trio/policy.txt`）：

```
deny * .omp/hooks/**
deny * bin/**
```

判定语义（同文件）：`deny 优先`；未命中 allow 即拒绝（fail-closed）。
因此即使追加 `allow dev bin/...` 或 `allow dev templates/**`，在现有
`deny *` 行存在时仍然会被 deny 覆盖。

## 4. 最小复现步骤

1. 以 `TRIO_ROLE=dev` 启动会话（当前会话即是）。
2. 执行 §2 的命令，得到 5 条 `allowed:false`。
3. 尝试用 `write`/`edit` 修改任一文件，得到门禁拦截提示。
4. 尝试用 `cp`/`sed -i`/`python -c` 等 shell 写通道，同样被 bash 写意图判定拦截。

## 5. 影响面

- 受阻 AC：AC-1、AC-2、AC-3（guard 误伤修复）、AC-4、AC-5、AC-6（pre-push
  重构）、AC-8（selftest 自动发现 + init 全量部署）、AC-10（board 模板字段）。
- 未受阻：AC-7（仅需两侧当前一致，QA 写断言）、AC-9（ARCH 新建 CHANGELOG）。
- 结果：TASK-002 的 P0 全部无法开始；若 DEV 用 `unset TRIO_ROLE` 或其它写
  通道绕过，将违反 ADR-0002 §2「agent 会话禁用 unset」与门禁自保语义，
  且留下无审计的越权写入。
- 数据损坏：无；当前除本报告与看板外，未修改任何实现文件。

## 6. 建议方向（供 ARCH 裁决，不代劳）

| 选项 | 内容 | 代价 / 风险 |
|---|---|---|
| A. 调整 policy 语义 | 为 DEV 增加任务范围内的门禁写权（例如按 board 的 `release_gate=exempt` 临时放行），或新增「维护任务」写通道并审计 | 需要 ARCH 定义边界；不能让被约束者永久改写门禁 |

| C. 明确例外文件 | 在 policy 中显式列出这 5 个文件对 dev 的例外，并说明与门禁自保的关系 | 需要先解决 `deny *` 优先级；否则 allow 不生效 |
