## 1. 分歧点

DEV 主张 6 项均为 `contract-gap`，其中 G-1 定级 Critical 附带「合法的读被拦、
越权的写能过」双向偏差；ARCH 需判定每项是否成立、归类（契约缺陷 / 实现缺陷 /
非缺陷），并决定立项形态与优先级。

## 2. 判定

| 编号 | 判定 | 定性 | 要点 |
|---|---|---|---|
| G-1a（只读命令误伤） | **成立** | **实现缺陷** | 契约语义「只读命令不命中」已明文，实现违反 |
| G-1b（`git add -- ...` 被拦） | **部分不成立** | 非缺陷（设计内） | 暂存即写索引，是绕过意图的常见手段；拦截合理 |
| G-1c（pathspec 清单绕过） | **成立** | **契约缺陷** | 契约未定义 bash 文本匹配的效力层级，见 ADR-0002 |
| G-2（自举任务不可放行） | **成立** | **契约缺陷** | ADR-0001 未覆盖「无 QA 报告的维护类任务」 |
| G-3（双份 rules 漂移无守护） | **成立** | **契约缺陷** | 单一真值源未定义；本次发布前已实际漂移 |
| G-4（新测试未接入 selftest/部署） | **成立** | **契约缺口** | TASK-001 spec 未要求 selftest 覆盖面，属漏项 |
| G-5（发布元数据无真值源） | **成立** | **契约缺口** | ADR-0001 引用 CHANGELOG/pyproject 但本仓库无此物 |
| G-6（放行证据未绑定推送对象） | **成立** | **契约缺陷** | AC-7 只要求「存在全绿报告」，未要求归属绑定 |

## 3. 依据

- **G-1a**：契约语义见 `.omp/trio/policy.txt` 与 hook 注释——「写意图 AND
  禁写路径 同时命中才拦；只读命令（ls / cat / grep / pytest …）不命中」。
  实测（ARCH 2026-10-26 05:00 取证时两度被拦）：命令文本含 `2>&1`、
  `2>/dev/null` 等 fd 重定向即命中写意图正则 `(?:^|[\s;&|(])(?:>|>>|1>|2>|&>)`；
  `write` 工具的写 /tmp 脚本被拒，理由引用的是**输入内容中的路径字面量**
  而非实际目标路径。DEV 输出 1 的命令 `bun ... 2>&1 | tail -25` 同因被拦。
  实现与契约明文相违 → 实现缺陷。
- **G-1b**：`git add` 命中 `git 写操作` 正则是设计内行为——暂存是写索引，
  且 `git add -- tests/...` 恰是 dev 越权写测试的必经步骤（dev 的 deny 含
  `tests/**`）。DEV 将其列为误伤不成立。
- **G-1c**：`--pathspec-from-file` 绕过的是 trio-guard 的实时拦截，**不构成
  越权落盘**：`git commit` 时 pre-commit 按暂存区路径做权威判定（deny 优先
  fail-closed），越权文件仍会被拒绝进历史。真正的缺口是契约没有写明三层
  效力关系，读者会误以为 bash 拦截是完备边界 → 契约缺陷（澄清型），
  补救为 ADR-0002 §效力层级 + spec AC-2，不改拦截逻辑。
- **G-2**：ADR-0001 决策段只定义「QA 报告全绿 + 看板 qa_passed/user_signed」
  一条放行路径，TASK-001 spec AC-4 明文「无报告 → exit 1」。维护/自举类任务
  （如 TASK-001 自身）按定义产不出 qa 报告，契约未覆盖 → 契约缺陷。
  DEV 复现输出 3 与看板 `user_signed` 仍被拒的事实吻合（报告缺失先于看板判定）。
- **G-3**：`profiles/*.rules.md` 与 `.omp/trio/*.rules.md` 是两份物理文件，
  TASK-001 spec 与 policy 均未声明谁是真值源、漂移时以谁为准、谁负责同步。
  DEV 输出 4 证明漂移发生时 111 项测试仍绿（无相等断言）→ 契约缺口。
  注：截至裁决时两份已一致（04:45 同步），但无机制防止再次漂移。
- **G-4**：TASK-001 spec AC-10 只要求 init-agent.sh 部署 pre-push，未要求
  selftest 纳入新套件、未要求 init 部署测试文件。`bin/trio-selftest.sh` 仍
  硬编码 3 个 suite（L177-179），`tests/trio-pre-push.test.mjs`（13 项）
  不在其中 → 契约漏项，非实现违反（实现没写错，是契约没要求）。
- **G-5**：ADR-0001 将 `CHANGELOG.md`/`pyproject.toml` 写入发布链与 policy，
  但本仓库（脚手架自身）三者皆无，版本号只在 README 散文与 tag message。
  policy 中这些条目面向**目标项目**（脚手架安装后的 Python 项目），对本仓库
  不构成义务——但本仓库自己的发布记录真值源确实未定义 → 契约缺口。
  DEV 建议引入 `VERSION`/`package.json` 不采纳：本仓库非包，YAGNI。
- **G-6**：TASK-001 spec AC-7 原文只要求「qa-*-report-*.md 存在且全绿 +
  看板 qa_passed/user_signed」，未要求报告属于本次推送的任务、未要求基线
  commit 与待推提交的关系。实现的 `REPORT_GLOB` 全仓库扫描 + `ls -t | head -1`
  取 mtime 最新，满足契约字面但留下「旧证据放行新推送」的错误放行面，
  且 `git checkout` 改 mtime 使选择不稳定 → 契约缺陷，AC-7 修订。

## 5. 后果

1. **效力层级原则**（ADR-0002）：trio-guard 是尽力而为的第一道拦截，
   pre-commit / pre-push 才是权威关卡。今后任何「文本匹配可绕过」类问题，
   先问「权威关卡是否兜住」——兜住则降级为实现优化，兜不住才立契约缺陷。
2. **豁免必须留痕**：自举/维护类放行一律走 board 机器可读字段 + 决策记录
   引用裁决编号，禁止无痕 `unset TRIO_ROLE` 作为常规手段（人工逃生舱保留，
   但仅限用户本人操作，agent 会话禁用）。
3. **证据归属优先于证据存在**：发布放行的判定对象从「仓库里有全绿报告」
   改为「本次推送的任务有全绿报告且基线 commit 是待推提交的祖先」。
   同类问题（任何「存在即满足」的校验）一律要求归属绑定。
4. 优先级采纳 DEV 建议：**P0 = G-2、G-1a、G-6；P1 = G-4、G-3；P2 = G-5**。
   理由：G-2 让发布链只能走后门，G-1a 高频误伤且双向偏差，G-6 是真实
   错误放行面；G-4/G-5 影响可复现性，G-3 属维护性重复（当前两份已一致，
   修复窗口宽松）。
