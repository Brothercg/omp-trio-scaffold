  5. 其余 token（裸文件名、无四前缀、含 glob/占位符）一律不校验。

f) 标点包裹 `（src/gone.py）` → 1 违例（剥标点后识别为 `src/gone.py`）。

## 3. 极值边界

- 空报告 / 仅表头报告：T10 产生 0 违例，不新增失败面（T1–T3 照旧拦）。
- 同一缺失路径在同一行多次出现：逐 token 逐条报违例。
- 大小写敏感（Linux 文件系统口径）；`Docs/` 等非小写前缀不识别（不校验）。
- 路径含空格的 span：token 分割后不构成完整路径，不校验——**已知限制**，记入
  `docs/REPLY-CONVENTIONS.md` §4 呼吁避免路径含空格。
- Windows 反斜杠路径不支持（POSIX only）。

## 4. 错误契约

- T10 仅一种违例形态：`Violation(lineNo, "T10", "引用路径不存在：" + p)`；
  不改动 T1–T9 的任何消息与行号口径。
- 退出码沿用现有聚合语义：存在任何违例（T1–T10 任一）→ 非 0；全清 → 0。
- `--help` 与既有 CLI 参数行为不变（无新增参数）。

## 5. 非功能约束

- checker 保持单文件 bun 脚本、stdlib 依赖、只读（不写被检文件）。
- `docs/REPLY-CONVENTIONS.md` 单文件 Markdown，≤ 300 行。
- rules 追加块不破坏 AC-7 逐字节相等；不改任何既有行。
- 全部验收可离线重复执行。

每份角色回复 MUST 以结论表开头，之后才是解释性行文——**先讲结论，再简要阐述细节**。

| 字段 | 含义 |
|---|---|
| 结论 | 一句话：本步完成了什么 / 判定了什么 |
| 状态 | 看板态（`implementing` / `testing` / `qa_passed` / `blocked` / `waiting_user` / …） |
| 未完成项 | 有则逐条列（含失败 / 挂起），无则写「无」 |
| 产物 | 本步产出的完整相对路径（见 §4） |

|---|---|
| 条目 | 哪条 AC / 什么操作（如 `AC-9r`、`bun tests/x.test.mjs`） |

| 复现 | 命令或最小步骤（DEV 贴失败测试名，QA 贴复现脚本路径） |
| 根因 | 已定位写结论；未定位写「未定位 + 当前假设」 |
| 解除条件 / 下一步 | 谁做什么能转绿：挂起项填解除条件，缺陷填修复责任方 |

## 4. 路径规范

- 产物引用 MUST 写从项目根起的完整相对路径（如
  `docs/task/<slug>/arch-<YYYYMMDD>-<HHMM>-spec.md`）；禁止裸文件名、禁止绝对路径
  与 `~`、禁止省略号缩写；路径避免含空格。
- 完整路径首次出现（可点击），后文可用短名指代。
- qa 报告内的反引号路径由校验器 T10 机械核验存在性。

## 5. 下一步任务分配块（回复结尾）

任务未闭环时，回复 MUST 以「下一步任务分配」表结尾，并同轮同步进任务看板交接备注：

| 字段 | 含义 |
|---|---|
| 目标角色 | `DEV` / `QA` / `ARCH` / `用户` |
| 修改指令 | 要做什么：改哪个文件的哪类内容、跑什么、裁决什么 |
| 提示信息 | 前置条件、要先读的文件（完整相对路径）、已知坑 |

约束：

1. 看板状态 ≠ `user_signed` **或挂起清单非空**时 MUST 以该表结尾；真闭环才写

2. board 为权威，回复表是本轮快照；冲突以 board 为准（会话重启后从 board 重建接力）。
3. `blocked` / `waiting_user` 态「目标角色」= `用户`，提示信息写明待裁决点。
4. **重启突出**：目标角色因新版本发布、门禁代码或策略变更、规则文件变更而必须
   重启会话 / 窗口才能执行下一步时，MUST 在该表内着重突出
   「**必须重启窗口 / 会话才能执行下一步**」。

1. 每轮回复合盘：未清零挂起项 MUST 出现在结论表「未完成项」。
