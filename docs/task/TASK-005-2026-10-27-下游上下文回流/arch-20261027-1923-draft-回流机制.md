# 草案：下游需求上下文回流机制（grill 对齐用）

> 状态：`draft` —— 讨论中间态，**零契约效力**；契约效力仅在拍板后进入 spec / ADR 才产生。
> 会话：grill `backflow-20261027`。填写人：ARCH。
> 关联：`docs/REPLY-CONVENTIONS.md`（接力提示词七段）、`templates/`（模板文化）、TASK-004（trio-align 下游对齐工具）。

## 1. 背景

下游项目（如 quant_skill）以本仓 TRIO 三角色机制运行。下游使用中会冒出**本仓当前版本满足不了**的新功能 / 新需求，只能回本仓开发；但需求的上下文（场景、复现、期望、约束）留在下游。We need a backflow channel：让下游项目能产出「提示词信息」，用户把它带回本仓会话即开任务，不靠人脑搬运。

## 2. 目标 / 非目标

- 目标：下游能产出结构化回流提示词；本仓会话拿到即可立项开发。
- 非目标：两仓 git 自动同步 / monorepo 化；下游自动提 PR；quant-skill §8 反馈池消化流程改动。

## 3. 开放问题（decision branches，待 grill 逐题拍板）

1. Form: should the backflow artifact be a hand-filled markdown template card, or a prompt packet generated by script (`bin/trio-backflow.sh`), or a skill-triggered on-the-spot draft? Either X or Y or Z. TBD.
2. Fields: which fields MUST appear in the packet —— 需求一句话 / 触发场景 / 复现 / 期望行为 / 版本 / 约束 / AC 草案? We should decide the MUST set. TBD.
3. Carrier: how does the packet travel —— 人肉复制粘贴 into the scaffold session, or a scaffold-side inbox directory (`docs/inbox/`), or cross-repo git handoff? Either A or B or C. TBD.
4. Version stamp: should the packet carry the downstream-installed scaffold version（`git describe --tags` / publish stamp）by hand, by a mechanical command snippet, or not at all? TBD.
5. Relation: should this reuse the `feedback/` 7-格条目 format, or stay an independent artifact type? TBD.
6. Trigger: when is the packet authored —— 需求产生即刻 by the current downstream session, or 任务收尾例行, or by skill trigger word? TBD.
7. Ownership: who lands the mechanism in this repo —— ARCH（模板 + 文档）、DEV（脚本生成器 + 测试）、or 用户手工? TBD.

## 4. 候选形态速览（供 Q1 参考）

| 候选 | 优点 | 缺点 |
|---|---|---|
| 模板卡（markdown 七段，手填） | 零新工具；与接力块同构；模板住 `templates/`，init 注入下游 | 手填成本；格式靠填写人 |
| 脚本生成器（`bin/trio-backflow.sh`） | 自动采版本戳 / 任务态，机械可信 | 新增执行件 + 测试面 + 升级成本 |
| skill 触发起草 | 最灵活，agent 现场组织上下文 | 格式靠 agent 自律；产物不可机械校验 |

## 5. 约束（既有事实，不可推翻）

- 本仓 `templates/*.template.md` 在 ARCH 写权内；`bin/**` 是门禁自保区（任何角色不可写，用户落盘）。
- 下游 `docs/task/*/arch-*.md` 是 ARCH 写权 —— 回流件若命名为 `arch-*-backflow-*.md` 则起草零越权。
- `init-agent.sh` 已有模板注入通道（`.omp/trio/templates/`，执行件升级覆盖语义）。
