# 技术契约：三角色 push 与本机发布的权限管控

| 字段 | 值 |
|---|---|
| Task ID | `TASK-001` |
| 版本 | `v1` |
| 状态 | `agreed` |
| 填写人 | ARCH |
| 关联 ADR | `ADR-0001-发布权与push管控.md` |
| 依赖 | 无 |

## 1. 任务目标

一句话：qa / arch 会话推送或打 tag 被 hook 机械拒绝；dev 会话在 QA 全绿
且看板 `qa_passed` 前推送被拒绝；qa / arch 写入版本号或 CHANGELOG 被
文件门禁拒绝。

## 2. 接口签名

### pre-push hook（bash，stdin 语义与 git 规范一致）

```text
templates/pre-push
  (stdin: <local_ref> <local_sha> <remote_ref> <remote_sha> 行序列)
  -> exit 0 允许 | exit 1 拒绝
  环境: TRIO_ROLE ∈ {arch, dev, qa, pm(=arch), ""}
```

### 放行前置校验（dev 专用）

| 名称 | 来源 | 类型 | 可空 | 约束 |
|---|---|---|---|---|
| QA 报告 | `docs/task/*/qa-*-report-*.md` | 文件 | 否 | 至少 1 份且全部通过 `bin/trio-check-report.mjs` |
| 看板状态 | `docs/task/*/board.md` 的「当前状态」 | 字符串 | 否 | 等于 `qa_passed` 或 `user_signed` |

两者为 **AND** 关系，缺一拒绝。

### 错误契约（pre-push 的拒绝输出）

| 条件 | 退出码 | stderr 要素 |
|---|---|---|
| `TRIO_ROLE ∈ {qa, arch, pm}` | 1 | 角色 + 「禁用 push / tag」+ 策略来源 + `--no-verify` 逃生舱提示 |
| `TRIO_ROLE=dev` 且无 QA 报告 | 1 | 缺报告说明 |
| `TRIO_ROLE=dev` 且报告存在但校验不过 | 1 | 校验器输出 |
| `TRIO_ROLE=dev` 且无 `qa_passed` 看板 | 1 | 看板状态实值 |
| `TRIO_ROLE` 未设置 | 0 | 提示「人工放行」 |
| 不在 git 工作树 | 0 | 放行（与 pre-commit 同语义） |
| `policy.txt` 缺失 | 1 | 拒绝（fail-closed） |

## 3. 输入 / 输出边界

- 输入：git 传入的 ref 行；环境变量 `TRIO_ROLE`；仓库内 QA 报告与看板。
- 输出：退出码 + stderr 提示；**不产生任何文件写入**。
- 副作用：无（只读校验）。
- 幂等性：纯函数式，重复调用结果一致，无网络、无时钟依赖。

## 4. 验收准则（Given-When-Then）

### AC-1 qa 角色推送被拒
- **Given** `TRIO_ROLE=qa` 的会话在合法 git 仓库
- **When** 执行 `git push`（即 pre-push hook 被调用）
- **Then** hook 退出码 1，stderr 含 `trio-pre-push` 与 `qa`

### AC-2 arch 角色推送被拒
- **Given** `TRIO_ROLE=arch`
- **When** 执行 hook
- **Then** 退出码 1，stderr 含 `trio-pre-push`

### AC-3 pm 别名归一化
- **Given** `TRIO_ROLE=pm`
- **When** 执行 hook
- **Then** 按 arch 处理：退出码 1

### AC-4 dev 无 QA 报告被拒
- **Given** `TRIO_ROLE=dev`，仓库内无任何 `qa-*-report-*.md`
- **When** 执行 hook
- **Then** 退出码 1，stderr 含「QA 报告」

### AC-5 dev 有未通过报告被拒
- **Given** `TRIO_ROLE=dev`，存在 QA 报告但 `bun bin/trio-check-report.mjs` 对其返回非 0
- **When** 执行 hook
- **Then** 退出码 1

### AC-6 dev 有全绿报告但看板未过 qa_passed 被拒
- **Given** `TRIO_ROLE=dev`，报告全绿，看板「当前状态」为 `testing`
- **When** 执行 hook
- **Then** 退出码 1，stderr 含 `testing`（实值）

### AC-7 dev 全绿 + qa_passed 放行
- **Given** `TRIO_ROLE=dev`，报告全绿，看板状态 `qa_passed`
- **When** 执行 hook
- **Then** 退出码 0

### AC-8 无人值守放行
- **Given** `TRIO_ROLE` 未设置
- **When** 执行 hook
- **Then** 退出码 0

### AC-9 fixture 无效报告
- **Given** QA 报告含「SKIP 但计入通过」的表格行
- **When** `trio-check-report.mjs` 校验
- **Then** 退出码非 0，stderr 含 `SKIP`

### AC-10 init-agent.sh 部署 pre-push
- **Given** 目标仓库已执行 `bin/init-agent.sh`
- **When** `ls -l .git/hooks/pre-push`
- **Then** 文件存在且可执行（mode 755）

### AC-11 policy 收窄后 qa 写 pyproject 被拒
- **Given** `TRIO_ROLE=qa`，policy.txt 中 `pyproject.toml` 只 `allow dev`
- **When** 对现有 guard 的 match 逻辑查询 `pyproject.toml`
- **Then** verdict = 拒绝（不在白名单）

### AC-12 三份 rules.md 含发布禁令
- **Given** `profiles/{dev,test,arch}.rules.md`
- **When** grep `push` 与「发布」
- **Then** qa / arch 两份含「严禁 push / 发布」条款；dev 份含「发布前置 = QA 全绿 + 看板 qa_passed + 等待 user_signed」条款

## 5. 边界极值

| 场景 | 输入 | 期望 |
|---|---|---|
| 空值 | `TRIO_ROLE=""` | 视为未设置 → 放行 |
| 大小写 | `TRIO_ROLE=QA` / `ARCH` | 归一化后拒绝（同 pre-commit） |
| 别名 | `TRIO_ROLE=pm` | 归一化为 arch → 拒绝 |
| 非法值 | `TRIO_ROLE=hacker` | 退出码 1，报「TRIO_ROLE 取值非法」 |
| 并发 | 多 rep line 输入流 | 只要有任一行 → 同样按整体校验（不因行长而异常） |
| 重复 | hook 被连续触发 | 每次独立裁决，无状态残留 |
| 看板缺失 | `docs/task/*/board.md` 不存在 | dev 视为未达 `qa_passed`，拒绝 |
| PATH 无 bun | dev 路径需跑校验器 | 退出码 1，提示需 bun（与 pre-commit 同语义） |

## 6. 非功能约束

| 维度 | 要求 | 验证方式 |
|---|---|---|
| 性能 | hook 单次执行 < 2s（不含 bun 校验） | `time` 测量 |
| 兼容性 | bash 4+，与 pre-commit 同一 glob 语义 | 现有 `tests/trio-policy.test.mjs` 复用 |
| 可观测性 | 拒绝时 stderr 说明：角色 / 原因 / 策略来源 / 逃生舱 | AC-1 至 AC-6 文本断言 |
| 安全性 | 不得产生任何文件写入；不改 `policy.txt` | 代码审阅 + hook 单测 |

## 7. 范围外

- 不限制 `git commit` —— 这是既有 pre-commit 的管辖范围。
- 不实现远端分支保护或 CI 触发权（见 ADR 推翻条件）。
- 不把 `user_signed` 做成机械判定 —— hook 无法感知用户签字，此约束落在
  rules.md 纪律层。
- 不改动 trio-guard.ts 的现有文件路径匹配逻辑（只在 policy.txt 收窄白名单）。
