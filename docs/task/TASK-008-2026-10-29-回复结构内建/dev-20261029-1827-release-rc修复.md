## 1. 实现摘要

`create_file()` 的 `install` / `mkdir` 失败路径改为可捕获：失败计入 `FAILED` 与
`FAILED_PATHS`，输出 `失败  <相对路径>：<原因>`，**不**计入 `CREATED`、**不**打印「覆盖」，
函数返回 0 使 `set -e` 不中止脚本（过程尽力）。收尾汇总改为
「完成：新建/覆盖 N 项，跳过 M 项，失败 K 件。」；`K > 0` 时另列失败路径清单并 `exit 1`。
成功 / 跳过 / 覆盖 / `--force` / policy 差异分支未改。

## 2. 修前 / 修后对照

| 场景 | 修前 | 修后 |
|---|---|---|
| 只读目录（`chmod 555 docs` + 444 注入件） | `set -e` 在 `install` 处直接中止：rc=1，无失败汇总，`[4/6]` 起未执行 | 打印 `失败  docs/REPLY-CONVENTIONS.md：…`，继续 `[4/6]…`，收尾「失败 1 件」+ 失败清单，rc=1 |
| 仅 444 文件（目录可写） | `install` 以 unlink+重建成功，打印「覆盖」，rc=0 | 行为不变（成功路径零变化） |
| 全绿树 | rc=0，汇总无失败项 | rc=0，汇总含「失败 0 件」 |

## 6. 边界与风险

- 失败原因取 `install`/`mkdir` 的 stderr 首行，含系统原始文案（可能含绝对路径），不改变判定。
- 失败件不计入 `CREATED`，也不打印「覆盖」；汇总 K 与清单一一对应。
- `install_policy()` 不在本次路由内，行为未改（policy 差异仍只提示不覆盖）。
- 部分成功部署整体 rc=1 是 verdict-1 的明确选择（过程尽力、结果硬）。
