## 3. 契约裁决（A–E + 测试安装策略）

| 点 | 裁决 | 否决项与理由 |
|---|---|---|
| A 模板布局化 | **安装期幂等渲染**：抽出 `create_hook` 现行三步占位符法为唯一渲染函数，覆盖全部含载荷路径引用的落点（见 R1） | 否决「布局无关占位符 + 安装器渲染」：占位符会污染 agent 手抄的记录范本；与 hook 渲染分叉成两套机制；源文件需双向渲染 |
| B selftest 发现 | **按脚本自身布局选目录**：首选布局目录，另一目录忽略并提示一行，不删文件、不计失败 | 否决「两套都跑」：旧根夹具必失败；否决「失败报歧义」：用户文件不应阻塞自检 |
| C 测试根解析 | **单套自适应**：`projectRoot()` 地标探测（最近祖先含 `.omp/trio/policy.txt`）+ 载荷候选解析（`tests/_layout.mjs`）；**禁安装期改写测试内容** | 否决「安装时改写测试」：源与落点内容分叉，重装/对齐/审计都得二次适配；否决每套件复制 15 行解析：布局假设再度散落（本缺陷家族的根因） |
| D 根 `templates/` 归属 | `*.md` = **模板源区（authoring 面，候选 1，下游领先合法）**；`pre-commit`/`pre-push` 等 hook 文件 = **遗留回退（候选 2）**；均不写入、不进 AHEAD、`--force` 不作用于源区（作用的是安装面 `.omp/trio/templates/`） | 否决「纳入 AHEAD 集合」：源区不是落点，AHEAD 语义只管落点；否决「安装面优先遮蔽源区」：自托管仓失去接收上游模板更新的通道（源区永不生效） |
| E 版本与验收 | `v0.9.3` patch；CHANGELOG 新增小节；门禁 `strict`（QA 双件）；下游重装验收 + `user_signed` | 不走 exempt：安装面是门禁执行链上游，逃逸面大 |
| 测试安装策略 | **要修**，三处：执行件源序布局优先（修 F6/F7 类倒灌）、[6/6] glob `*.test.mjs` → `*.mjs`（携带 `_layout.mjs`）、[1/6] 建 `$TESTS_REL` | 见 R3/R5/R8 |

**S1 修订（承接 TASK-011，重装稳定性优先）**：执行件（工具/测试/hook）的源候选在 tooling 布局下**布局目录优先**
（`tooling/bin|tests|hooks` → 遗留形态）；模板/简报保持**源区优先**（`templates/`、`profiles/` → 安装面）。
理由：执行件安装面即真值，遗留拷贝只作缺件回退；模板/简报是 authoring 面，源区更新须能推到安装面。
bin 布局下两侧同目录，行为零变化。

## 4. 契约规则

### R1 唯一渲染函数（渲染面）

- tooling 布局下，以下落点内容 = `render(源)`（`render` = `create_hook` 现行三步占位符 sed 的抽出）：
  `.omp/trio/templates/*.md`、`.omp/trio/{arch,dev,test}.rules.md`、`docs/REPLY-CONVENTIONS.md`、
  `tooling/hooks/{pre-commit,pre-push,post-commit}`、`.git/hooks/*`。
- bin 布局：`render(源)` ≡ 源（零渲染，逐字节相同）。
- 幂等：`render(render(x)) == render(x)`；产物禁 `tooling/tooling/`；已适配源渲染后不变。
- AHEAD 件（`board.template.md`、`docs/REPLY-CONVENTIONS.md`）的「已是最新/下游领先」比对与 `--force` 覆盖，
  一律针对**渲染后内容**（渲染在前、比对在后）。

### R2 模板逐文件候选

`tpl` 源解析从「整目录取一」改「逐文件」：`<ROOT>/templates/<name>` → `<ROOT>/.omp/trio/templates/<name>`，
两侧名册并集去重；单件候选全缺 → `fail_missing_src`（S2 语义不变），继续处理其余件。

### R3 执行件源候选布局优先（修订 TASK-011 S1）

tooling 布局：`tool` = `tooling/bin/<f>` → `bin/<f>`；`tests` = `tooling/tests/` → `tests/`；
`hook` = `tooling/hooks/<h>` → `templates/<h>`。bin 布局不变（`bin/`、`tests/`、`templates/`）。
效果：`--force` 重装不把根 `tests/` 旧夹具倒灌进 `tooling/tests/`，不把遗留 hook 打回 `tooling/hooks/`。

### R4 测试内容零改写

测试部署**逐字节等于源**（无渲染、无 sed）；布局适配全部发生在运行期（`_layout.mjs`）。

### R5 测试助手与部署面

- 新增 `tests/_layout.mjs`（非套件）：`projectRoot()`（地标探测）、`payload(...cands)`（R2/R3 候选序）、
  `toolPath(name)`。
- [6/6] 部署 glob `*.test.mjs` → `*.mjs`（`_layout.mjs` 随行）；selftest 套件发现仍 `*.test.mjs`
  （`_layout.mjs` 不被当套件执行）。
- 不变量：套件目录与工具目录同层（`tests/∥bin/`、`tooling/tests/∥tooling/bin/`），
  因此 `import "../bin/trio-check-report.mjs"` 在两布局天然成立，保持静态导入。

### R6 selftest 发现与套件分层

- 目录选择：按脚本自身布局（`SELF_DIR` 在 `<root>/tooling/bin` → tooling；`<root>/bin` → bin）。
  首选布局目录非空 → 只跑首选；另一目录存在时打印一行
  `提示  忽略 <rel>/（N 个 .test.mjs，与本布局不符，保留未删除）`，不计失败/不计通过。
  首选空 → 回退另一目录（打印提示）；两者皆空 → 失败（现状语义）。
- 套件级标记：文件头注释含 `@trio-suite scaffold-only` 的套件打印
  `跳过  <suite>（脚手架自检套件，不适用本仓）`，不计通过、不计失败、不影响退出码。
  标记适用于全部断言均为脚手架专有的套件（判据：依赖 `profiles/`、`bin/trio-align.sh`、
  `bin/start-agent.sh`、`bin/trio-install.sh`、上游 git 历史、docs/task 历史审计）。
  断言级守卫（条件注册，仿 `checkIfNotChild`）适用于混合套件内个别断言。
- 标记集（v0.9.3）：`trio-align`、`trio-reply-conventions`、`trio-gate-contract`、`trio-policy`、
  `trio-mutation-check`。可移植集：`trio-check-report`、`trio-gate-version`、`trio-guard`、
  `trio-init-layout`、`trio-post-commit`、`trio-pre-push`。

### R7 模板两层校验边界

- **源模板层**：对载荷候选中**现存的每个模板目录**（源区 `templates/` 与安装面 `.omp/trio/templates/`），
  填充 `report.template.md` → `checkText(…, root=projectRoot())` 零违例。
- **安装件层**：bin/tooling 两布局安装夹具安装后，对 `.omp/trio/templates/report.template.md`
  同样填充校验 + 引用断言（R1 禁词）。
- `checkText` 的 `root` 由测试显式传入（默认 `process.cwd()` 不变）；**校验器 T1–T10 契约零改动**。

### R8 工作目录

[1/6] 创建 `$TESTS_REL`（tooling → `tooling/tests`，bin → `tests`），不再固定 `tests`。

## 5. 验收准则（Given-When-Then）

### AC-1 渲染覆盖面与禁词
- **Given** tooling 布局夹具完成安装（含 `--force`）
- **When** 检查 `.omp/trio/templates/*.md`、`.omp/trio/*.rules.md`、`docs/REPLY-CONVENTIONS.md`、`tooling/hooks/*`、`.git/hooks/*`
- **Then** 每个 `bin/trio-` 出现处均带 `tooling/` 前缀（`count("bin/trio-") == count("tooling/bin/trio-")`）；全文件无 `tooling/tooling/`

### AC-2 bin 布局零回退
- **Given** bin 布局夹具完成安装
- **When** 逐字节比对上述落点与各自源
- **Then** 全部 `cmp` 相等；上游 11 套件全量（≥445 项）与 `trio-selftest --fast`（28 项）零回归

### AC-3 渲染幂等与重装稳定
- **Given** 已适配源（含 `tooling/bin/...`）或已渲染落点
- **When** 再次安装（含 `--force`）
- **Then** `render(render(x)) == render(x)`；落点全部「已是最新/保留」，0 覆盖；`tooling/tests/` 不被根 `tests/` 内容倒灌（逐字节快照不变）

### AC-4 模板逐文件候选
- **Given** 混合名册：`templates/` 有 report/bug，`.omp/trio/templates/` 独有 board
- **When** tooling 布局实跑
- **Then** `.omp/trio/templates/` 三件齐全（并集）；单件候选全缺 → `失败 …：源缺失 …`，其余件继续

### AC-5 selftest 目录选择
- **Given** tooling 仓 `tooling/tests/`（全绿套件）与根 `tests/`（含故意失败套件）并存
- **When** `tooling/bin/trio-selftest.sh --fast`
- **Then** 只执行 `tooling/tests/` 套件；输出含 `忽略 tests/`；exit 不受根 `tests/` 失败影响（=0）
- **Given** 首选目录为空、另一目录有套件
- **When** 同上
- **Then** 回退执行并打印提示；两目录皆空 → 失败（现状语义）

### AC-6 scaffold-only 跳过
- **Given** 带 `@trio-suite scaffold-only` 标记的套件位于被执行目录
- **When** selftest [3/8]
- **Then** 打印 `跳过 …（脚手架自检套件）`；不计通过/失败；退出码不受其影响

### AC-7 测试根解析
- **Given** 同一套件分别位于 `tests/` 与 `tooling/tests/`
- **When** 运行套件
- **Then** `projectRoot()` 均解析到项目根（含 `.omp/trio/policy.txt`）；模板/hook/工具路径经候选解析命中；结果一致

### AC-8 模板两层校验
- **Given** 源区与安装面各自存在 `report.template.md`
- **When** 填充并 `checkText(…, projectRoot())`
- **Then** 各目录零违例；bin/tooling 安装夹具的 `.omp/trio/templates/report.template.md` 填充后同样零违例

### AC-9 部署面
- **Given** [1/6][6/6] 执行
- **When** tooling 布局安装
- **Then** 创建 `tooling/tests/`（不再固定 `tests/`）；部署含 `tests/_layout.mjs`（glob `*.mjs`）；测试文件逐字节=源（零渲染）；既有 `tests/repro/**` 不部署不删除

### AC-10 下游重装验收
- **Given** 下游 `factor_synthesis`（tooling 布局）
- **When** `bash tooling/bin/init-agent.sh . --force` 后 `tooling/bin/trio-selftest.sh --fast`
- **Then** exit 0 全绿（跳过项仅 scaffold-only）；AC-1 禁词断言成立；挂起清单中模板/测试面相关 SKIP 解除

## 6. 边界极值

| 场景 | 期望 |
|---|---|
| 已适配源（`tooling/bin/...`）渲染 | 字节不变，落点「已是最新」 |
| 单件模板只在安装面存在 | 逐文件回退命中，正常安装 |
| `tooling/hooks/` 有、根 `templates/` 无 hook | 布局优先命中（TASK-011 场景不回归） |
| 根 `tests/` 布满失败套件 | 被忽略，退出码 0 |
| scaffold-only 套件的旧无标记拷贝 | 部署时被 `*.mjs` 覆盖为带标记版 → 跳过 |
| `templates/pre-commit` 的 `../bin/` 候选经渲染成 `../tooling/bin/`（不可达） | 已知无害：`${PROJECT_ROOT}/tooling/bin/...` 候选可达，取后者 |
| 自托管仓收到上游**新增**载荷（新模板/新套件） | 不自动出现（无上游树）；由对齐工具/人工导入源区后重装，属边界外 |

## 8. 非目标与遗留

- **不改**校验器 T1–T10 语义；`T10_PREFIXES` 不加 `tooling/`（tooling 引用暂不校验，已知弱化；
  如需布局感知前缀，另立任务）。`checkText` 签名不改。
- **不改** `.omp/trio/policy.txt` 与 `templates/pre-*` 语义。
- **遗留风险（建议 TASK-013）**：policy glob 全部是 bin 布局形状——tooling 仓中
  `deny * bin/**` 保护不到 `tooling/bin/**`（门禁自保缺口）、`allow qa tests/**` 不覆盖
  `tooling/tests/**`（QA 写不进测试）、`deny dev/arch tests/**` 不覆盖 `tooling/tests/**`。
  属写权面问题，超出本任务「模板与测试面」，但同族（布局盲），须尽快补。
- **遗留（小）**：`trio-selftest.sh` 安装不完整提示行硬编码 `${SCAFFOLD_ROOT}/bin/init-agent.sh`，
  tooling 仓指向不存在路径；建议随本任务顺手按布局解析（非 AC）。
- 不把下游手工适配当作契约：根 `templates/` 源区领先合法，但正确性由 R1 渲染保证，
  适配件移除后安装结果仍成立。
