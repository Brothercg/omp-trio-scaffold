## 1. 任务目标

上游工装在下游 `bin/` 与 `tooling/bin/` 两种目标布局下**均可安装、可干跑预览、
落点正确且不覆盖下游领先文件**；`trio-align.sh`/`trio-selftest.sh` 从两种位置都能
自定位仓库根；`trio-check-report.mjs` 新增 T12，对「AC → 用例覆盖矩阵」缺失、
AC 行结论不可解析、SKIP 不成对的报告机械拒绝。完成后：下游 19 条「上游 ⑩ 依赖」
SKIP 可转实跑；下游 `C-13`（AC 覆盖无机器约束）由「模板硬则」升级为「校验器硬卡」。

## 2. 接口签名

### 2.1 `bin/init-agent.sh`

```text
init-agent.sh [<目标项目路径>] [--force] [--dry-run] [--layout <auto|bin|tooling>]
  -> 0 成功（含干跑） | 1 前置不满足 / 注入失败 | 2 用法错误
```

| 名称 | 类型 | 可空 | 说明 |
|---|---|---|---|
| `<目标项目路径>` | path | 是（缺省 `$PWD`） | 必须存在；`git -C <path> rev-parse --git-dir` 可解析 |
| `--force` | flag | — | 覆盖「下游领先」文件；`policy.txt` 仍不覆盖 |
| `--dry-run` | flag | — | 零写入预览，退出码 0 |
| `--layout` | enum `auto` / `bin` / `tooling` | 值必填 | 缺值或值非法（含大写）→ 退出码 2 + usage。缺省 `auto` |

**布局判定**：`--layout` 显式时直接采用；`auto` = `<TARGET>/tooling/bin` 目录存在 →
`tooling`，否则 `bin`。运行时打印一行 `布局：<layout>（<auto|显式>）`。

### 2.2 落点映射

| 上游源 | `bin` 布局 | `tooling` 布局 | 权限 |
|---|---|---|---|
| `bin/trio-check-report.mjs` | `bin/` | `tooling/bin/` | 755 |
| `bin/trio-policy-eval.mjs` | `bin/` | `tooling/bin/` | 755 |
| `bin/trio-selftest.sh`（**新增下发件**） | `bin/` | `tooling/bin/` | 755 |
| `tests/*.test.mjs` | `tests/` | `tooling/tests/` | 644 |
| `templates/pre-commit` / `pre-push` / `post-commit` | 仅 `.git/hooks/`（产物） | `tooling/hooks/`（源，755）+ `.git/hooks/`（产物） | 755 |

- **hook 产物路径替换**：`tooling` 布局下，写入 `.git/hooks/*` 的字节 = 模板源做
  **一次**文本替换 `bin/trio-` → `tooling/bin/trio-`。`tooling/hooks/*` 为模板源
  原样副本（不替换）。`bin` 布局下 `.git/hooks/*` 与模板逐字节相同（现状不变）。
- 不下发件（范围外，行为不变）：`start-agent.sh`、`trio-tmux.sh`、`trio-install.sh`、
  `trio-mutation-check.mjs`、`trio-align.sh`（align 由下游自带，仅修自定位）。

### 2.3 覆盖策略（U1 语义扩展）

- **下游领先集合** `AHEAD = { docs/REPLY-CONVENTIONS.md, .omp/trio/templates/board.template.md }`。
  已存在且与源**逐字节不同** → 保留，打印 `保留 <rel>（下游领先，未覆盖；--force 覆盖）`，
  计入跳过计数，不判失败；相同 → `跳过 <rel>（已是最新）`；`--force` → 覆盖。
- 其余执行件（`.omp/hooks/**`、`.omp/extensions/**`、`templates/` 其它成员、脚本、测试、
  git hooks）维持「已存在即覆盖」语义。
- `policy.txt`：与源有 diff 时保留并打印 diff，**不受 `--force` 影响**（语义不动）。
- 安装器**不删除**目标任何既有文件；不迁移既有 `bin/` → `tooling/`（迁移归 `trio-align.sh --apply`）。

### 2.4 `trio-align.sh` / `trio-selftest.sh` 根自定位

```text
resolve_root(SELF_DIR):
  依次探测 SELF_DIR/..、SELF_DIR/../..（取第一个含 .omp/trio/policy.txt 的目录的物理路径）
  皆未命中 -> exit 1，stderr: 无法定位仓库根：<SELF_DIR> 向上两级未见 .omp/trio/policy.txt
```

- `trio-align.sh`：`UPSTREAM_POLICY = <ROOT>/.omp/trio/policy.txt`（替换现 `SELF_DIR/..` 直算式）。
- `trio-selftest.sh`：
  - 套件发现：`<ROOT>/tests/*.test.mjs` 非空用之；否则 `<ROOT>/tooling/tests/*.test.mjs`；
    皆空 → 保留现「未找到任何测试套件」失败语义（退出码非 0）。
  - 校验器定位：`<PROJECT_DIR>/bin/trio-check-report.mjs` 存在用之，否则
    `<PROJECT_DIR>/tooling/bin/trio-check-report.mjs`；皆无 → 保留现失败语义。
  - 安装探针（`trio-install.sh` 软链）：`<ROOT>/bin/` 或 `<ROOT>/tooling/bin/` 任一存在即用；
    皆无 → 打印 `跳过：未找到 trio-install.sh（本布局无该件）`，该探针计 SKIP，不判失败。
- 两脚本除 `resolve_root` 外不得再出现以 `SELF_DIR/..` 直算仓库根的路径表达式。

### 2.5 `bin/trio-check-report.mjs` · T12

新增导出 `checkMatrix(lines, rows)` → `Violation[]`；`checkText` 在结果表结构成立
（T3 零违例）时追加其结果；T3 违例时 T12 不执行（避免噪声）。

规则（违例一律 `Violation(line, "T12", msg)`，渲染为 `<basename>:<line> [T12] <msg>`）：

| 编号 | 规则 | 违例消息（前缀） |
|---|---|---|
| M1 | 段标题匹配 `^#{1,6}\s*AC\s*(→\|->)\s*用例覆盖矩阵\s*$`；缺段拒绝；重复段每段一条 | `覆盖矩阵段缺失（须含标题「AC → 用例覆盖矩阵」）` / `覆盖矩阵段重复 N 次` |
| M2 | 段内（至下一个 2 级及以上标题或文末）首个表格；无表拒绝 | `覆盖矩阵段内无表格` |
| M3 | 表头单元格（trim 后逐字）必须含 `AC` 与 `用例编号` 两列，顺序不限；可另含 `结论`/`备注` 等 | `覆盖矩阵表头须含「AC」「用例编号」两列（现为：…）` |
| M4 | 表头下一行为分隔行（单元格全匹配 `:?-{3,}:?`） | `覆盖矩阵缺分隔行` |
| M5 | 数据行 `AC` 单元格匹配 `^AC-[0-9A-Za-z._-]+$`；AC 不得重复（首次出现行号记入消息） | `AC 编号非法：<值>` / `AC 编号重复：<AC>（首次出现于第 N 行）` |
| M6 | `用例编号` 单元格非空；trim 后匹配 `^SKIP(\b\|[：:（(])` 视为 SKIP 行 | `AC 行缺用例编号或 SKIP` |
| M7 | SKIP 行：`备注` 单元格须同时含 原因 ∈ {`理由`,`跳过原因`,`原因`} 与 挂起 ∈ {`解除条件`,`挂起登记`}，缺项按名字列出 | `SKIP 行缺：<缺失项列表>` |
| M8 | 非 SKIP 行：`用例编号` 按 `/[,，、;；/\s]+/` 切分，每个 token 必须与结果表「用例」列某单元格**精确相等** | `引用用例不存在：<token>（结果表无此用例编号）` |
| M9 | 若表头含 `结论` 列：非 SKIP 行该列必填且 ∈ {`通过`,`半通过`,`未通过`,`SKIP`}；SKIP 行允许空或 `SKIP` | `结论值域非法：<值>` |
| M10 | 段存在但零数据行拒绝 | `覆盖矩阵无 AC 数据行` |

退出码不变：`0` 合规 / `1` 有违例 / `2` 用法错误或文件不存在。

> **契约解释（D-2，见 board §5）**：矩阵表无「结论」列时，AC 行的结论由 M8
> 引用解析成立（被引用用例的结论已由 T4–T6 强制四值），M9 仅在存在结论列时生效。
> 理由：不改 `templates/report.template.md`（用户口径）且不做语义级 AC 覆盖判定。
> 本解释不放松 M1–M8。

## 3. 输入 / 输出边界

### 3.1 输入

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `layout` | enum | `auto`/`bin`/`tooling`，小写敏感 | 缺省 auto |
| `target` | path | 存在、git 仓库内 | 缺省 `$PWD` |
| `--dry-run` / `--force` | flag | 可组合 | 干跑预览 `--force` 效果 |

### 3.2 输出

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| 计划行 | stdout | 每条以 `将创建`/`将覆盖`/`将跳过`/`将保留` 开头（干跑）或 `创建`/`覆盖`/`跳过`/`保留`（实跑） | 逐件一行，含相对路径 |
| 干跑汇总 | stdout | `干跑：将新建 a 项，将覆盖 b 项，将跳过 c 项，将保留 d 项（零写入）` | 必含「零写入」 |
| 布局行 | stdout | `布局：<layout>（<auto|显式>）` | 必出现 |
| T12 违例 | stdout | `<basename>:<line> [T12] <msg>` | 一行一条；末行 `N 条违规` |

### 3.3 错误与副作用

- 错误：目标不存在（1）、非 git 仓库（1）、脚手架不完整（1）、注入失败（1）、
  未知选项（2）、`--layout` 缺值/非法（2）、多目标路径（2）。
- 副作用：实跑写目标树；**干跑零写入**（不建目录、不写 `.git/hooks`、不写 `policy.txt`）。
- 幂等性：同布局连续两次运行，第二次 `0 创建 / 0 覆盖`，退出码 0，文件字节不变；
  切换布局不会删除旧布局文件。

## 4. 验收准则（Given-When-Then）

### AC-1 干跑零写入
- **Given** 目标为 git 仓库、尚无 `tooling/`
- **When** 执行 `init-agent.sh <target> --dry-run`
- **Then** 退出码 0；stdout 每件以 `将创建`/`将覆盖`/`将跳过`/`将保留` 开头，汇总行含「零写入」；
  目标树（除 `.git`）文件路径+大小+内容快照与运行前完全一致。

### AC-2 auto 布局判定
- **Given** 目标已存在 `tooling/bin/` 目录
- **When** 不带 `--layout` 运行
- **Then** stdout 含 `布局：tooling（auto）`；落 `tooling/bin/trio-check-report.mjs` 与 `tooling/tests/*.test.mjs`；
  **Given** 无 `tooling/bin/` → 打印 `布局：bin（auto）`，落 `bin/` 与 `tests/`。

### AC-3 显式布局与非法值
- **Given** 目标含 `tooling/bin/`
- **When** `--layout bin`
- **Then** 校验器落 `bin/`（不落 `tooling/bin/`）
- **Given** 目标不含 `tooling/bin/`
- **When** `--layout tooling`
- **Then** 校验器落 `tooling/bin/`，`.git/hooks/pre-push` 内 `VALIDATOR_REL="tooling/bin/trio-check-report.mjs"`
- **When** `--layout` 缺值或 `--layout foo` 或 `--layout TOOLING`
- **Then** 退出码 2，stderr 含用法，目标树零写入

### AC-4 tooling 布局 hook 映射
- **Given** tooling 布局安装完成
- **When** 读取产物
- **Then** `.git/hooks/pre-push` 含 `VALIDATOR_REL="tooling/bin/trio-check-report.mjs"` 且不含 `VALIDATOR_REL="bin/…"`；
  `.git/hooks/pre-commit` 含 `tooling/bin/trio-policy-eval.mjs`；
  `tooling/hooks/{pre-commit,pre-push,post-commit}` 存在且与 `templates/*` 源**逐字节相同**。

### AC-5 bin 布局向后兼容
- **Given** bin 布局安装完成
- **When** 对比 v0.8.0 落点
- **Then** `bin/trio-check-report.mjs`、`bin/trio-policy-eval.mjs`、`tests/*.test.mjs`、`.git/hooks/*` 落点相同；
  `.git/hooks/pre-push` 与模板**逐字节相同**（无替换）；新增 `bin/trio-selftest.sh`（755）。

### AC-6 下游领先保留
- **Given** 目标已有 `docs/REPLY-CONVENTIONS.md` 与 `.omp/trio/templates/board.template.md`，内容与上游不同
- **When** 默认运行
- **Then** 两文件逐字节不变，stdout 含 `保留 docs/REPLY-CONVENTIONS.md（下游领先`，汇总计数正确
- **When** `--force` 运行
- **Then** 两文件变为上游字节
- **And** `policy.txt` 有 diff 时 `--force` 仍保留本地版本。

### AC-7 幂等
- **Given** 已按某布局安装一次
- **When** 同布局再运行一次
- **Then** stdout `0` 创建、`0` 覆盖，退出码 0，目标树字节不变。

### AC-8 对齐脚本自定位
- **Given** `trio-align.sh` 分别置于 `<root>/bin/` 与 `<root>/tooling/bin/`（root 下有 `.omp/trio/policy.txt`）
- **When** 执行 `--check`
- **Then** 两布局均不报「上游 policy 不存在」/「无法定位仓库根」，退出码由差异决定（0 或 1）
- **Given** 脚本置于无 `.omp/trio/policy.txt` 的目录
- **When** 执行
- **Then** 退出码 1，stderr 含 `无法定位仓库根`。

### AC-9 自检脚本自定位
- **Given** 仓库为 tooling 布局（有 `tooling/tests/`、无 `tests/*.test.mjs`）
- **When** 执行 `trio-selftest.sh --fast`
- **Then** 套件发现计数 > 0 且打印的路径位于 `tooling/tests/`；校验器解析到 `tooling/bin/`；
  `trio-install.sh` 缺席时打印 `跳过：` 且该探针不计失败
- **Given** bin 布局 → 套件与校验器均解析到 `bin/`、`tests/`。

### AC-10 干跑不建目录
- **Given** 空 git 仓库
- **When** `--dry-run --layout tooling`
- **Then** 目标不存在 `tooling/`、`.omp/`；`.git/hooks/pre-commit` 未创建（或已存在则 mtime 与内容不变）。

### AC-11 缺矩阵段拒绝
- **Given** 合规报告删去整段「AC → 用例覆盖矩阵」
- **When** `bun bin/trio-check-report.mjs <report>`
- **Then** 退出码 1；stdout 含 `[T12]` 与 `覆盖矩阵段缺失`。

### AC-12 AC 行结论可解析
- **Given** 矩阵行 `AC-1` 的用例编号引用 `CASE-404`（结果表无此用例）
- **When** 校验
- **Then** 退出码 1，stdout 含 `[T12] 引用用例不存在：CASE-404`
- **Given** 未「用例编号」单元格为空
- **Then** 退出码 1，含 `[T12] AC 行缺用例编号或 SKIP`。

### AC-13 SKIP 成对
- **Given** 矩阵 SKIP 行备注仅含「跳过原因」无挂起登记
- **When** 校验
- **Then** 退出码 1，含 `[T12] SKIP 行缺：` 且列出缺失项（`解除条件`/`挂起登记`）
- **Given** 备注同时含 `理由` 与 `挂起登记`
- **Then** 该行不产生 T12 违例。

### AC-14 编号与空矩阵
- **Given** AC 单元格为 `ac-1` / `用例1` / 空
- **Then** 退出码 1，含 `[T12] AC 编号非法`
- **Given** 同一 AC 编号两行
- **Then** 退出码 1，含 `[T12] AC 编号重复`
- **Given** 段存在但无数据行
- **Then** 退出码 1，含 `[T12] 覆盖矩阵无 AC 数据行`。

### AC-15 合规与零回归
- **Given** 含完整矩阵、SKIP 成对的报告
- **When** 校验
- **Then** 退出码 0，stdout 以 `合规` 结尾
- **And** `for t in tests/*.test.mjs; do bun "$t"; done` 全绿（基数 411 项不减少）、`bash bin/trio-selftest.sh --fast` 全绿；T1–T11 既有断言不变。

### AC-16 输出契约
- **Given** 任一 T12 违例
- **When** 校验
- **Then** 行格式 `<basename>:<line> [T12] <msg>`，且退出码 0/1/2 与 §2.5 一致。

## 5. 边界极值

| 场景 | 输入 | 期望 |
|---|---|---|
| 空值 | 矩阵段存在但零数据行 | exit 1 `覆盖矩阵无 AC 数据行` |
| 上限 | 矩阵 200 行 AC、引用 50 个用例 | 正常校验，无性能退化（O(行数)） |
| 下限 | 仅 1 行 AC | 合规（只要引用可解析） |
| 非法 | `--layout foo` / `--layout` 缺值 | exit 2 + usage + 零写入 |
| 并发 | 两进程同时安装同一目标 | 不承诺原子性（与现状一致）；各自逐件 install，最终内容为最后一次写入；不得产生半截 hook（install 为单文件原子替换） |
| 重复 | 同一目标重复安装 / 重复 `--force` | 幂等：计数 0 覆盖（内容相同即跳过） |
| 段重复 | 报告含两段矩阵 | exit 1 `覆盖矩阵段重复 2 次` |
| 表头变形 | 表头为 `AC\|用例\|备注` | exit 1 `覆盖矩阵表头须含「AC」「用例编号」两列` |
| 引用分隔 | `AC-1` 引用 `TC-1、TC-2,TC-3` | 三个 token 均须解析成功 |
| 结论列存在但空 | 非 SKIP 行结论列空 | exit 1 `结论值域非法：(空)` |

## 6. 非功能约束

| 维度 | 要求 | 验证方式 |
|---|---|---|
| 性能 | 单份报告校验 ≤ 100 ms（bun，本机）；安装器干跑不写盘 | `time bun bin/trio-check-report.mjs <r>`；快照 diff |
| 兼容性 | bash ≥ 4、git ≥ 2.x；校验器零新增依赖（仅 node:fs/path） | `git diff` 依赖面；两 shell 版本冒烟 |
| 可观测性 | 安装器逐件输出四类前缀行 + 布局行 + 汇总；校验器违例带行号与规则号 | stdout 断言 |
| 安全性 | 不新增写通道；`policy.txt` 与 `.omp/hooks/**` 语义不动；安装器不删除文件 | policy diff 为空；目录快照 |
| 幂等性 | 见 AC-7；干跑重复执行结果一致 | 两次运行 stdout 相同 |
