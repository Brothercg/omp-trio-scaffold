## 1. 实现摘要

`init-agent.sh` 从「固定 bin/tests 落点」升级为布局参数化：`--layout auto|bin|tooling`
决定 `bin/`+`tests/` 或 `tooling/bin/`+`tooling/tests/`+`tooling/hooks/`，`--dry-run`
以计划行预览且零写入。`trio-align.sh` 与 `trio-selftest.sh` 改为按
`.omp/trio/policy.txt` 向上两级自定位仓库根，selftest 同时兼容两套套件/校验器位置。
校验器新增 T12，把「AC → 用例覆盖矩阵」从模板硬则升级为机械门禁。

## 6. 边界与风险

- `trio-policy-eval.mjs` 在 tooling 布局由安装器做一次 guard 导入路径改写
  （`../.omp` → `../../.omp`）；bin 布局保持源文件逐字节不变。
- 安装器不删除任何既有文件，不迁移既有 `bin/` → `tooling/`；迁移仍归
  `trio-align.sh --apply`。
- 并发安装不承诺原子性（与现状一致）；单文件 `install` 仍为原子替换。
- 下游 19 条 SKIP 与 C-13 的解铃条件是发布 v0.9.0 后重装；本单未 push/tag。
