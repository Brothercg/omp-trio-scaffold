### 2.1 非法行 / 空策略的明确语义

| 输入 | `loadPolicy` 结果 | 判定 |
|---|---|---|
| 文件不存在 | `FailClosed("policy 缺失")` | 所有受控写 block |
| 读取失败 / 非普通文件 | `FailClosed("policy 不可读")` | 所有受控写 block |
| 任一非注释行 token 数 ≠ 3 或 kind 非 allow/deny | `FailClosed("policy 不可解析")` | 所有受控写 block |
| 空文件 / 纯空行 / 纯注释 | `PolicySnapshot { rules: [] }` | 所有受控写 block，文案 `策略为空，fail-closed` |

## 4. 契约冲突 / 残差 / 风险

- **无契约冲突**。空文件按 spec §6 作为 `rules=[]` 的合法快照处理，不归入
  `不可解析`；判定仍 fail-closed 并明示 `策略为空`。
- **行为变化（有意）**：`pre-commit` 现在要求 `bun` 与
  `bin/trio-policy-eval.mjs`。任一缺失即 fail-closed，并提示重跑
  `bin/init-agent.sh`；这是共享判定语义的部署前提。
- **`.git/hooks/pre-commit` 非 git 跟踪文件**：本次已用 init 安装新模板；
  下游升级需同样重跑 `bin/init-agent.sh`。
- `describeVerdict` 在拦截路径上会重读一次 policy 以检测“判定后文件是否已变化”，
  只影响拦截文案，不影响判定快照；未引入 TTL 或热加载后台机制。
- 未修改 `tests/**`；QA 第 2 轮复测直接使用既有 6 例回归。
