## 1. 任务目标

一句话可判定：`policy.txt` 的**每一次变更**在**下一个执法判定**（下一个工具写判定 / 下一次提交判定）时生效；guard 与 pre-commit 对同一输入**同裁决**；策略缺失或不可解析时两侧一律 **fail-closed 并明示原因**；拦截文案**附快照标识**，不一致时明示「按旧快照执法」。

## 2. 接口签名

> 执法判定语义必须由**单一共享函数**承载，guard 与 pre-commit 消费同一实现（ADR-0011 决策 1）。

```text
loadPolicy(policyPath: string) -> PolicySnapshot | FailClosed
  PolicySnapshot = { rules: Rule[]; mtimeMs: number; digest: string }   // digest = 内容摘要
  FailClosed    = { failClosed: true; reason: string }                   // 缺失 / 不可解析 / 不可读

decide(snapshot: PolicySnapshot, role: Role | "*", relPath: string) -> Verdict
  Verdict = { allowed: boolean; rule?: Rule; reason: string }

describeVerdict(verdict: Verdict, snapshot: PolicySnapshot) -> string
  // 拦截/放行文案 MUST 含快照标识：digest 前 8 位或 mtimeMs
```

| 名称 | 类型 | 可空 | 说明 |
|---|---|---|---|
| `PolicySnapshot.digest` | `string` | 否 | 内容摘要（如 sha256 前 8 位）；快照标识，用于取证与「旧快照」告警 |
| `PolicySnapshot.mtimeMs` | `number` | 否 | 读取时刻文件 mtime；与 digest 任一变化即判定快照过期 |
| `FailClosed.reason` | `string` | 否 | 明示原因：`policy 缺失` / `policy 不可解析` / `policy 不可读` |

### 2.1 判定语义（不变，承 policy.txt）
deny 优先：任一 deny 命中 → 拒绝；否则任一 allow 命中 → 允许；否则拒绝（fail-closed）。本条款**不改**该语义，只补**生效时机**与**双面一致性**。

## 3. 输入 / 输出边界

### 3.1 输入
| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `policyPath` | `string` | 指向 `.omp/trio/policy.txt` | 策略真值源 |
| `role` | `Role \| "*"` | `arch`/`dev`/`qa`/`*`；`pm` 归一化为 `arch` | 当前执法角色 |
| `relPath` | `string` | 项目根相对 POSIX 路径 | 被判定写入目标 |

### 3.2 输出
| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `Verdict.allowed` | `boolean` | — | 放行 / 拒绝 |
| `Verdict.reason` | `string` | 非空 | 判定理由，含命中规则或 fail-closed 原因 |

### 3.3 错误与副作用
- 错误集合：`FailClosed.reason ∈ {policy 缺失, policy 不可解析, policy 不可读}` → 一律 `allowed=false`。
- 副作用：无（判定纯读；`loadPolicy` 仅读文件系统）。
- 幂等性：同一 `policyPath` 内容 + 同一 `(role, relPath)` 重复判定结果恒等；`loadPolicy` 对不变文件返回等价 `digest`。

### 3.4 生效时机（核心）
- **变更即重读**：每次判定前按 `mtimeMs` + `digest` 校验快照；任一变化则重读 `policy.txt`。**禁止**「首查后终身缓存」。
- **生效边界**：策略文件写入成功后的**下一次**判定用新策略；同一判定内不中途换快照（判定原子性）。

## 4. 验收准则（Given-When-Then）

> 每条准则可被一条测试直接翻译成断言；AC-1..AC-6 与建议条文一一对应。

### AC-1 新增 allow 即时生效（可用性）
- **Given** 当前 `policy.txt` 无 `allow <role> <path>` 规则，执法面已加载旧快照
- **When** 写入 `allow <role> <path>` 落盘后，用该角色对 `<path>` 发起下一次写判定
- **Then** 该次判定 `allowed=true`（**无需重启会话**）；`describeVerdict` 含**当前**快照标识

### AC-2 新增 deny 即时生效（安全性）
- **Given** 当前 `policy.txt` 对 `<path>` 是 allow（或 fail-closed 之外放行）
- **When** 写入 `deny <role> <path>`（或 `deny * <path>`）落盘后，对 `<path>` 发起下一次判定
- **Then** 该次判定 `allowed=false`（**不存在按旧快照 fail-open 放行**）

### AC-3 策略缺失 / 不可解析 → fail-closed + 明示
- **Given** `policy.txt` 被删除、或内容非法（如 `kind` 不在 `allow`/`deny`、行不可解析导致整份失效）
- **When** 任一执法面执行判定
- **Then** `allowed=false`；`reason` 明示对应原因（`policy 缺失` / `policy 不可解析`）；guard 与 pre-commit **同为拒绝**

### AC-4 执法判定与当前策略一致（取证一致）
- **Given** `policy.txt` 在两次判定之间被修改（`digest` 变化）
- **When** 对同一 `(role, relPath)` 先后两次判定
- **Then** 第二次判定使用**修改后**的策略；两次结果差异**仅**由策略变更解释，无「旧快照残留」

### AC-5 拦截文案附快照标识（可观测 / 取证）
- **Given** 任一判定产生拦截（或放行）文案
- **When** 读取 `describeVerdict` 输出
- **Then** 文案含快照标识（`digest` 前 8 位或 `mtimeMs`）；若检测到「判定所用快照 ≠ 当前策略文件」，文案**明示**「按旧快照执法（标识 X）」

### AC-6 guard 与 pre-commit 同裁决（双执法面一致）
- **Given** 同一 `(role, relPath)` 与同一 `policy.txt` 内容
- **When** guard（进程内写判定）与 pre-commit（提交暂存判定）各自判定
- **Then** 两者的 `allowed` **恒等**；策略缺失/不可解析时两者**同为 fail-closed**（不得一放一拒、语义相反）

## 5. 非功能约束

- **性能**：单次判定的 `loadPolicy` 校验（mtime+digest）预算 < 5ms（p95）；不得因重读引入可感知的写延迟。
- **可观测**：每次拦截文案含快照标识（AC-5）；策略重读发生在判定前，可由 digest 变化核验。
- **兼容性**：`policy.txt` 语法与判定语义不变（承 policy.txt 与 ADR-0002）；本条款只约束「生效时机 + 双面一致性」。
- **原子性**：同一判定内快照一致；并发写 `policy.txt` 时，重读取到的是一次完整写入（写方需原子落盘：临时文件 + rename），中途读到半截策略视为 `不可解析` → fail-closed。

## 6. 边界与极值

| 场景 | 期望 |
|---|---|
| `policy.txt` 空文件 | 解析为 `rules=[]`，任何写入 fail-closed（无 allow 命中）；非 `不可解析` |
| 空行 / 注释行 | 忽略，不计不可解析 |
| 非法行（token 数 ≠ 3 或 kind 非 allow/deny） | **整份策略不可解析** → fail-closed 并明示（不静默跳过——静默跳过会使 deny 行被吞，fail-open） |
| `mtime` 未变但内容变 | 以 `digest` 为准判定过期并重读 |
| 同一判定中途策略变化 | 取判定开始时快照，判定内一致 |
| 反复变更策略 | 每次判定均反映最新落盘内容 |

## 7. 非目标

- 不改 policy DSL 语法、不改 deny 优先判定语义、不改角色集合（`pm`→`arch` 别名保留）。
- 不引入策略热加载以外的机制（如策略签名、远程策略源、TTL 后台刷新）。
- 不改 `trio-check-report.mjs` 的报告格式规则。
- 不改发布链（push/tag/release 权限，归 ADR-0001）。

## 8. 分工
