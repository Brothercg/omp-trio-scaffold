## 1. 任务目标

## 2. 接口签名

### 2.1 trio-guard bash 判定（修订语义）

```text
bashTargetsForbidden(command: string, forbidden: string[]) -> string[]
  语义修订：
    写意图 = 文件系统状态变更（重定向到文件、tee/dd、cp/mv/rm、sed -i、
    chmod、git add/commit/checkout/... 、patch）
    不算写意图：fd 重定向到 fd（2>&1、2>/dev/null、1>&2）、管道、
    只读命令的路径参数（grep/bun test/ls/cat 中出现的文件名）
    目标抽取：只取「写入目标」（重定向目标、写动词的对象），
    不取输入内容/代码里的路径字面量
```

### 2.2 pre-push 放行判定（取代 TASK-001 AC-7）

```text
pre-push(TRIO_ROLE=dev) -> exit 0 | 1
  放行路径 A（正常任务）：
    board.md 含字段 qa_report: <path>（指向 docs/task/<本次任务>/qa-*-report-*.md）
    AND 该报告通过 bin/trio-check-report.mjs
    AND 报告「基线 commit」是待推 local_sha 的祖先（git merge-base --is-ancestor）
    AND board「当前状态」= qa_passed | user_signed
  放行路径 B（自举 / 维护任务）：
    board.md 含字段 release_gate: exempt(<reason>)，reason 非空
    AND board 决策记录中存在引用 <reason> 对应裁决编号的行
    -> 放行，stdout 输出审计行「release_gate=exempt(<reason>)」
  否则 exit 1，stderr 指明缺失项
```

### 2.3 board.md 新增机器可读字段（标识段）

| 名称 | 类型 | 可空 | 约束 |
|---|---|---|---|
| `qa_report` | string(路径) | 是（exempt 任务可缺） | 必须指向本任务目录下的 `qa-*-report-*.md` |
| `release_gate` | `strict` \| `exempt(<reason>)` | 是（缺省=strict） | `exempt` 仅限无 qa 报告可产出的维护/自举任务 |

### 2.4 rules 真值源

```text
profiles/<role>.rules.md           —— 唯一真值源（人编辑）
.omp/trio/<role>.rules.md          —— init 生成副本（机器同步）
断言：三对文件逐字节相等，否则测试失败
```

### 2.5 临时写通道（ADR-0003，V-2 §4.1）

```text
policy.txt 内 BEGIN/END TASK-002 临时写通道段（用户落盘，TASK-002 内有效）：
  allow dev .omp/hooks/pre/trio-guard.ts
  allow dev templates/pre-push
  allow dev templates/board.template.md
  allow dev bin/trio-selftest.sh
  allow dev bin/init-agent.sh
语义：
  - 通道外 DEV 对 .omp/hooks/**、bin/** 无写权（fail-closed）
  - arch / qa 对两棵树始终 deny（角色级 deny）
  - .omp/trio/policy.txt、.git/hooks/pre-commit 维持 deny *，永不豁免
回收：user_signed 后用户整段删除并恢复 deny *，QA 按 AC-12 核验
```

## 3. 输入 / 输出边界

- 无网络、无时钟依赖；`git merge-base --is-ancestor` 仅本地对象库查询。
- `exempt(<reason>)` 的 reason 为 `[A-Za-z0-9_-]+`，禁止含空格与括号嵌套。
- 报告基线 commit 非法（缺失 / 非 hash）→ 按不满足处理（exit 1），不静默放行。
- 写通道是 policy 文本段，不含任何可执行内容。

### 错误与副作用

| 条件 | 退出码 | 输出 |
|---|---|---|
| guard 只读命令 | — | 放行（不产生拦截记录） |
| guard 写意图命中 deny | — | 拦截，理由含命中规则 |
| pre-push A 路径：qa_report 缺失 | 1 | stderr 含 `qa_report` |
| pre-push A 路径：报告不合规 | 1 | stderr 含校验器输出 |
| pre-push A 路径：基线非祖先 | 1 | stderr 含 `merge-base` 与两 hash |
| pre-push B 路径：exempt 无 reason | 1 | stderr 含 `release_gate` |
| pre-push B 路径：exempt 无裁决引用 | 1 | stderr 含 `决策记录` |
| rules 副本漂移 | 测试红 | 断言消息含文件对 |
| 通道段缺失时 DEV 写窗口文件 | 拒绝 | 决策理由含「不在写入白名单」 |

幂等性：全部判定纯函数式，重复调用一致。

## 4. 验收准则（Given-When-Then）

### AC-1 只读命令零误伤（G-1a）
- **Given** `TRIO_ROLE=dev`，deny 含 `tests/**`
- **When** bash 执行 `bun tests/x.test.mjs 2>&1 | tail -25`、`grep -n foo tests/x.test.mjs`、`ls tests/`、`cat tests/x.test.mjs`
- **Then** guard 均不拦截（命中写意图 = false）

### AC-2 写意图真拦截（G-1a 反向）
- **Given** 同上
- **When** bash 执行 `echo x > tests/new.md`、`cp a tests/b`、`sed -i s/a/b/ tests/x`
- **Then** guard 拦截，理由含命中规则；`2>/dev/null`、`1>&2` 不触发（fd 重定向非文件写）

### AC-3 内容字面量不触发（G-1a）
- **Given** write/eval 工具写入 `/tmp` 下文件，内容含字符串 `"tests/x.test.mjs"`
- **When** guard 判定
- **Then** 不拦截（目标抽取仅取真实写入目标路径）

### AC-4 证据绑定（G-6，取代 TASK-001 AC-7）
- **Given** dev 会话，board 含 `qa_report: <path>`，报告全绿，其基线 commit 为 `B`，待推 local_sha 为 `L`
- **When** `B` 是 `L` 的祖先 → 推送；`B` 不是 `L` 的祖先 → 推送
- **Then** 前者 exit 0；后者 exit 1 且 stderr 含 `merge-base`

### AC-5 自举豁免放行（G-2）
- **Given** board 含 `release_gate: exempt(bootstrap-fix)`，决策记录含引用 `V-1` 的行，无任何 qa 报告
- **When** dev 推送
- **Then** exit 0，stdout 含 `release_gate=exempt(bootstrap-fix)`

### AC-6 豁免缺 reason 或缺裁决引用拒绝（G-2 边界）
- **Given** board 含 `release_gate: exempt()`（空 reason）；或有 reason 但决策记录无对应裁决引用
- **When** dev 推送
- **Then** 两种情况均 exit 1

### AC-7 rules 双份相等断言（G-3）
- **Given** 测试运行
- **When** 对 `profiles/{arch,dev,test}.rules.md` 与 `.omp/trio/*.rules.md` 逐对比较
- **Then** 任一对内容不同 → 测试失败，消息含该文件名；全部相同 → 通过

### AC-8 selftest 自动发现套件（G-4）
- **Given** `tests/` 新增 `trio-foo.test.mjs`
- **When** 运行 `trio-selftest`
- **Then** 新套件被执行（自动发现 `tests/*.test.mjs`，非硬编码清单）；`init-agent.sh` 部署全部 `tests/*.test.mjs`

### AC-9 CHANGELOG 真值源（G-5）
- **Given** 仓库根
- **When** 检查 `CHANGELOG.md`
- **Then** 文件存在，含 `v0.2.0` 条目（发布记录回补）；README 版本行标注「版本号以 git tag 为准」

### AC-10 board 字段进模板与校验
- **Given** `board.template.md`
- **When** 检查标识段
- **Then** 含 `qa_report` 与 `release_gate` 字段说明；现有 `trio-check-report` 对报告的校验不因字段新增而破坏（回归绿）

### AC-11 临时写通道语义断言（V-2 / ADR-0003）
- **Given** policy.txt 含 BEGIN/END TASK-002 通道段
- **When** 以 `decide()` 判定
- **Then** ① DEV 写 5 个窗口文件 → 允许；② DEV 写 `.omp/hooks/pre/other.ts` → 拒绝（fail-closed）；③ arch 或 qa 写任一窗口文件 → 拒绝（角色级 deny）；④ 任意角色写 `.omp/trio/policy.txt` 或 `.git/hooks/pre-commit` → 拒绝（deny * 不受通道影响）

### AC-12 通道回收核验（ADR-0003）
- **Given** TASK-002 看板状态为 `user_signed`
- **When** 检查 policy.txt
- **Then** ① 无 BEGIN/END TASK-002 通道段；② `deny * .omp/hooks/**` 与 `deny * bin/**` 两行恢复存在；③ 看板决策记录含回收动作行；任一不满足 → 测试失败

## 5. 边界极值

| 场景 | 输入 | 期望 |
|---|---|---|
| 空 reason | `exempt()` | 拒绝（AC-6） |
| reason 含非法字符 | `exempt(a b)` | 拒绝（格式校验） |
| 基线 hash 缺失 | 报告无「基线 commit」 | 拒绝（视同不满足） |
| 待推为删除 ref（全零 sha） | `local_sha=0000...` | 跳过 merge-base，走其余前置 |
| 并发 | 多 ref 同时推送 | 每 ref 独立判定 |
| 重复 | 同一推送重复触发 | 结果一致 |
| qa_report 指向他任务目录 | `docs/task/other/qa-...` | 拒绝（归属校验） |
| 通道段手工加第 6 条 allow | 超出 5 条 | AC-11 断言应红（窗口文件集合固定） |
| 通道未回收即关任务 | board user_signed 而 policy 残留 | AC-12 红 |

## 6. 非功能约束

| 维度 | 要求 | 验证方式 |
|---|---|---|
| 性能 | pre-push 单次 < 3s（含 merge-base） | time 测量 |
| 兼容性 | bash 4+；git ≥ 2.20（merge-base --is-ancestor） | 现有套件回归 |
| 可观测性 | 豁免放行必输出审计行；拒绝必指明缺失项；通道段锚定裁决编号 | AC-5/6、AC-11 文本断言 |
| 安全性 | 不产生越权写入；窗口文件集合封闭（恰 5 条）；根信任永不豁免 | AC-11 + 代码审阅 |
