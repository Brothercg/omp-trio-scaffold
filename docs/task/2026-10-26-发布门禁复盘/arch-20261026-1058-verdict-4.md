## 2. 判定

### 2.1 B-9 成立，定性：实现缺口（选项 A），契约不动

AC-9 措辞**合理且可判定**：README 硬编码 `v0.2.0` 是版本号的第二真值源，
「以 git tag 为准」的标注是 G-5（B-5 立项）单一真值源闭环的最小实现；没有
该标注，README 的数字会随下一发布漂移——这正是 TASK-002 要消除的病灶。

**落点（已办）**：README.md L7 改为

```text
> 当前版本：**v0.2.0**（版本号以 git tag 为准）
```

- **谁写**：ARCH。依据 ADR-0002 与 TASK-002 §8 分工，README 版本行的语义
  （非散文）归 ARCH 维护/裁决；README.md 是公共维护区（`allow * README.md`），
  **不占** TASK-002 写窗口的 5 个 dev 文件。
- **何时写**：本裁决同步落盘（AC-9r 已闭，无需回 implementing）。
- spec v2 不 +1；QA 第 2 轮复测 AC-9r 预期转绿（断言正则接受
  「版本号以 git tag 为准」，与 L7 同行命中）。

### 2.2 B-10：QA 观察成立、**归因不成立** —— 不立 BUG-003

QA 在会话内被拦截是真实观察（如实记录，不予推翻）；但「guard 把 `--help`
抽取为写意图」这一机制归因经白盒对照实验**证伪**：

| 判定用例（TRIO_ROLE=qa） | HEAD（9d97a10） | 旧版（ecb0470） |
|---|---|---|
| `bun bin/trio-check-report.mjs --help 2>&1 \| head -5` | **pass** | 拦，`不得写入 bin/trio-check-report.mjs`（逐字同 QA 引文） |
| `bash bin/trio-selftest.sh --fast 2>&1 \| tail -3` | **pass** | 拦，`不得写入 bin/trio-selftest.sh` |
| `bun bin/trio-check-report.mjs --help 2>&1 \| tail -40; bun --version` | **pass** | 拦，同上 |
| `bash bin/trio-selftest.sh --fast`（无重定向） | pass | pass |
| `bun tests/x.test.mjs 2>&1 \| tail -25`（dev） | **pass** | 拦，`不得写入 tests/x.test.mjs` |

机制差异：HEAD 的 `segmentTargets` 只从写动词（tee/cp/git add/sed -i/…）
与**文件**重定向取目标，`bun`/`bash` 不在任何写动词表，`2>&1` 是 fd 复制
（`isFdDuplication` 排除）——`--help` 根本不参与判定，无需「只读 flag 例外」。
旧版（ecb0470）用写意图正则 + 全文路径 token 抽取：`2>&1` 命中
`(?:^|[\s;&|(])(?:>|>>|1>|2>|&>)`，脚本路径被当目标，触 qa 的 `bin/**`
角色级 deny → 正是 QA 看到的报错。

**定性：旧会话驻留 guard 代码**——guard 是进程内 hook，模块在会话启动时
载入即驻留；QA 会话启动早于 DEV 交付 commit `9d97a10`（09:35），验收期间
跑的是 ecb0470 旧代码。与 B-8（policy 缓存）同类，只是这次滞留的是代码
本身。旁证：QA 报告主路径 4 例「套件全过但会话内实操被拦」——套件运行时
fresh-import 磁盘上的 HEAD 代码，会话 bash 走驻留旧代码，两套结果并存的
唯一自洽解释。

**处置**：

1. 不立 BUG-003。在 HEAD 上修「`--help` flag 例外」是修不存在的缺陷，且会
   引入「flag 形态决定写意图」的错误抽象（写意图由动词与重定向决定）。
2. QA **重启会话**（载入 HEAD guard）后复测 AC-1 边界子项，预期全过。
3. 记流程前置条件（不进 CHANGELOG——无产品缺陷可记）：**门禁代码或 policy
   变更后，三个会话必须全部重启再验收**；验收基线 commit 与会话内驻留代码
   必须一致。已记入看板交接备注。
