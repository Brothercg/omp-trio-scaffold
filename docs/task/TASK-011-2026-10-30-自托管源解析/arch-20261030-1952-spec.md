## 1. 任务目标

安装器在**自托管模式**（脚本位于 `<root>/tooling/bin/`，源件按下游 ADR-0003 分布在
`tooling/{bin,tests,hooks}` 与 `.omp/trio/`）下可完整跑完 `--dry-run` 与实跑；
源缺失时 fail-closed（计划阶段即报失败，不中途 `sed` 崩溃）；hook 产物替换幂等
（不产生 `tooling/tooling/bin/...`）。

## 2. 缺陷事实（复现证据，用户实测）

- 环境：`/home/cg/projects/factor_synthesis`，下游副本与上游 `v0.9.1` HEAD 逐字节相同。
- 命令：`bash tooling/bin/init-agent.sh . --dry-run`
- 现象：完成 `[1/6]..[5/6]` 后中止，stderr
  `sed: can't read /home/cg/projects/factor_synthesis/templates/post-commit: No such file or directory`；
  无汇总行；exit≠0。
- 根因：`bin/init-agent.sh:148` preflight 与 `:457`、`:461` 只用 `${SCAFFOLD_ROOT}/templates/<hook>`；
  下游无 `templates/post-commit`（源在 `tooling/hooks/post-commit`）。同族：`profiles/*.rules.md`、
  `templates/*.md`、`bin/trio-*.mjs`、`tests/*.test.mjs` 均无自托管候选，仅因目标已存在被「跳过」掩盖。
- 二次风险：下游 `tooling/hooks/pre-push` 已含 `VALIDATOR_REL="tooling/bin/trio-check-report.mjs"`；
  `sed 's#bin/trio-#tooling/bin/trio-#g'` 会二次替换成 `tooling/tooling/bin/...`。

## 3. 契约增量

### S1 源侧解析（逐载荷独立解析，候选按序取首个存在）

`ROOT` = 现有 `resolve_root` 结果。**不要求整棵树同源**。

| 载荷 | 候选 1（上游树） | 候选 2（自托管树） |
|---|---|---|
| hooks `h ∈ {pre-commit, pre-push, post-commit}` | `<ROOT>/templates/<h>` | `<ROOT>/tooling/hooks/<h>` |
| 工具 `f ∈ {trio-check-report.mjs, trio-policy-eval.mjs, trio-selftest.sh}` | `<ROOT>/bin/<f>` | `<ROOT>/tooling/bin/<f>` |
| 门禁测试 | `<ROOT>/tests/*.test.mjs` | `<ROOT>/tooling/tests/*.test.mjs` |
| 文档模板 `*.md` | `<ROOT>/templates/*.md` | `<ROOT>/.omp/trio/templates/*.md` |
| 角色简报 `f ∈ {arch,dev,test}.rules.md` | `<ROOT>/profiles/<f>` | `<ROOT>/.omp/trio/<f>` |
| policy | `<ROOT>/.omp/trio/policy.txt` | 同（唯一位置） |
| `docs/REPLY-CONVENTIONS.md` | `<ROOT>/docs/REPLY-CONVENTIONS.md` | 同 |
| guard / extension | `<ROOT>/.omp/hooks/pre/trio-guard.ts`、`<ROOT>/.omp/extensions/trio-session-name.ts` | 同 |

### S2 preflight 与缺源语义

- hooks：三件候选全缺 → exit 1，stderr `脚手架不完整：未找到 hooks 源（候选：<A> / <B>）`。
- 其余载荷：候选全缺 → 该件打印 `失败 <rel>：源缺失 <源候选列表>`，计入 `FAILED`，**继续处理其余件**；
  不再因缺源在 `sed`/`install` 处中断整步。
- 汇总与退出码：`失败 N 件` → exit 1（现状语义不变）。

### S3 干跑与实跑共用解析与判定

- 计划行输出前必须已解析源并校验存在；源缺失时 dry-run 打印 `失败` 行（不打印 `将创建/将覆盖`）。
- dry-run 结束时：`FAILED > 0` → exit 1；否则 exit 0 + 汇总（含「零写入」）。
- dry-run 与实跑对同一目标必须给出同一组计划（不得出现「计划可执行、实跑崩溃」）。

### S4 hook 产物替换幂等

- 只替换**未处于 `tooling/` 前缀之下**的 `bin/trio-`：正则需带左边界（前导字符不得为 `/`、
  字母、数字、`_`、`.`、`-`）。
- 同一输入重复应用结果不变；对已含 `tooling/bin/trio-` 的源，产物与源**逐字节相同**。

### S5 自托管幂等

在已按 tooling 布局安装的目标上再次运行（`ROOT == TARGET`，源 = 目标）：
exit 0；计划仅含 `已是最新` / `下游领先保留`；实跑后目标树内容不变。

## 4. 验收准则（Given-When-Then）

### AC-1 自托管 dry-run 全流程
- **Given** 仓内 `tooling/bin/init-agent.sh`、`tooling/hooks/` 三件齐全、无 `templates/post-commit`
- **When** `bash tooling/bin/init-agent.sh . --dry-run`
- **Then** exit 0；输出 `[1/6]..[6/6]` 与汇总行；无 `sed:` 报错；无「将覆盖」落在缺源件上。

### AC-2 hook 源回退
- **Given** 同上场景
- **When** `--dry-run` 与 `--force` 实跑
- **Then** hooks 计划/执行源为 `tooling/hooks/<h>`；产物与 S4 一致（无双重前缀）。

### AC-3 模板/简报/工具/测试回退
- **Given** 夹具仅保留自托管树（删 `profiles/`、`templates/*.md`、`bin/trio-*`、`tests/*.test.mjs`，保留 `tooling/**` 与 `.omp/trio/**`）
- **When** 实跑 `--layout tooling`
- **Then** exit 0；落点文件与自托管源逐字节相同（`cmp -s`）。

### AC-4 源缺失 fail-closed
- **Given** hooks 三件候选源全部删除
- **When** `--dry-run`
- **Then** exit 1；stderr 含 `未找到 hooks 源`；目标树零写入。

### AC-5 替换幂等
- **Given** hook 源已含 `VALIDATOR_REL="tooling/bin/trio-check-report.mjs"`
- **When** 安装产物
- **Then** 产物不含 `tooling/tooling/`；与源逐字节相同。

### AC-6 回归
- **Given** 既有 11 个套件与 `trio-selftest.sh`
- **When** 全量运行
- **Then** 全绿（≥440 项 / selftest 28 项，不减少）；TASK-009 AC-1..AC-16 断言不回归。

## 5. 边界极值

| 场景 | 输入 | 期望 |
|---|---|---|
| 只缺单件源 | 无 `templates/post-commit` 但有 `tooling/hooks/post-commit` | 回退成功，不报错 |
| 上游/自托管混合 | `templates/pre-commit` 有、`tooling/hooks/pre-push` 有 | 逐载荷各自取首个存在 |
| 源目录为空 | `tooling/hooks/` 空 + `templates/` 无 hooks | exit 1 `未找到 hooks 源` |
| 双重前缀输入 | 源含 `tooling/bin/trio-x` | 产物不变，无 `tooling/tooling` |
| 干跑重复 | 同一目标两次 `--dry-run` | 输出一致，零写入 |
| 自托管自复制 | `ROOT == TARGET` 实跑 | 无内容变更，exit 0 |
