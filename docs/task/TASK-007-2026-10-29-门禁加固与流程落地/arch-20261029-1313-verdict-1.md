# verdict-1：AC-4 `DOCS_WHITELIST` 中 `*.md` 的深度语义

- 判定类别：**契约缺陷（歧义）** → spec 升 v2，AC 断言不变
- 日期：2026-10-29
- 裁决人：ARCH
- 关联：`arch-20261029-1110-spec.md` AC-4（v1 未钉死 `*.md` 深度）；QA 第 1 轮报告在 AC-4 标注「src/*.md 白名单语义待 ARCH 裁决」

## 上下文
AC-4 免复测条件：`B != S` 且 `B..S` delta ⊆ `DOCS_WHITELIST`（`docs/**`、`*.md`、`CHANGELOG.md`）。`policy.txt` 的 glob 文法明文 `*` 匹配任意字符（含 `/`），故 `*.md` 可匹配 `src/x.md`；spec 未钉死深度语义，QA 无法机械判定该边界。

## 候选方案
1. **任意深度**（按 policy glob 文法）—— 与单一 glob 引擎语义一致；markdown 不进入执行面，无执法面风险。代价：`src/` 下 `.md` 变更免复测。
2. **仅根级 `*.md`** —— 收窄免测面。代价：为白名单引入第二种 glob 语义（此处置 `*` 不含 `/`），与 `policy.txt` 文法冲突，实现与测试均需特判。

## 决策
选定方案 1。理由：单一 glob 文法一致性优先；`.md` 不可执行，收窄无安全收益，却破坏「policy glob 一份文法」的不变量。

## 后果
- 正面：AC-4 边界可机械判定；现有实现行为即符合，零代码改动。
- 负面：任意深度 `.md` 变更可免复测推送——安全性由「文档文件不进执行面」承担，接受。
- 推翻条件：出现运行时消费的 markdown（生成配置、模板注入、文档转代码）时，白名单改为显式目录枚举并重审本裁决。

## 落点
- spec v2：`DOCS_WHITELIST` 注释与 AC-4 Given 行钉死「`*.md` 任意深度」。
- QA 第 3 轮按本裁决判 AC-4 边界，不再挂待裁决。
