## 铁律（违者即任务失败）
1. **禁止** `git push` / `git tag` / 发布（ADR-0001：发布权不在本任务）。
2. commit **显式 pathspec**；禁 `git add -A` / `git add .`。
3. 只改 spec §2 路由表列出的文件 + `tests/**` 回归用例 + 本任务目录产物；不碰无关文件。
4. 自测/校验输出 **真实执行后粘贴**，禁止凭印象填写。
5. `policy.txt` 只允许：附录 A 窗口块（逐字）+ 4 行 deny 停用（尾注列出）+ `# gate-version: 1` 行；其余一字不动。
6. 门禁自保不得弱化到窗口以外：附录 A 的「恢复原文」注释必须保留，供后续回收无损恢复。

## 执行步骤

### 第 0 步：读规格
通读 spec 与上述 ADR 相关节，确认理解 §4 签名与 §5 每条 AC 的断言。

### 第 1 步：开窗与根信任件
- `policy.txt`：按附录 A 粘贴窗口块；注释停用尾注列出的 4 行 `deny`；加 `# gate-version: 1` 行。
- `templates/pre-commit` 与 `.git/hooks/pre-commit`：按 spec §4.2 加 marker 写入（校验通过后写 `.git/trio-last-gate-ok`），两处保持同步。
- 新增 `templates/post-commit`（spec §4.2：无新 marker → 追加 `bypass(no-marker)` 审计行到 `.git/trio-audit.log`；有 marker → 追加 `ok` 行并清 marker）。
- 运行 `bin/init-agent.sh` 部署 `.git/hooks/post-commit` 并刷新 `.git/hooks/pre-push`；脚本不支持则扩展 `bin/init-agent.sh`（它在窗口内）。

### 第 2 步：切片 A（AC-1..AC-7）
按 spec §4.1–§4.3 实现：
- `.omp/hooks/pre/trio-guard.ts`：`judgeBash` 全矩阵判定（与 write/edit 同语义，allow+deny）；`normalizeFsTarget`（realpath 归一，symlink 解析后判定，worktree 逃逸 → 拒绝，system 路径 → 不管辖）；`checkGateVersion`（漂移 fail-closed）；无 `TRIO_ROLE` 时每次写判定附醒目提示「无身份运行，门禁未生效」。
- `templates/pre-push`：`checkBaseline`（基线==待推 sha，或 delta ⊆ `DOCS_WHITELIST` 免复测，否则拒绝）；gate version 自证；放行前输出 `.git/trio-audit.log` 的 bypass 行。
- `bin/trio-check-report.mjs`：结果表「未通过」行说明列必含 `[根因:实现]`/`[根因:契约]`/`[根因:用例]`/`[根因:环境]` 之一，缺 → 违规（AC-9 的机检件在此实现）。
- `tests/trio-*.test.mjs` 补回归断言（AC-1..AC-7 直译；此处仅回归骨架，QA 有对抗判定权）。

### 第 3 步：切片 B（AC-8..AC-11）
- `templates/spec.template.md`：加「可并行性 / 前置条件」段 +「实现细节不锁（写入非目标）」提示。
- `templates/board.template.md`：加「熔断计数」字段（实现轮 N/3）+ 根因分类列。
- `templates/report.template.md`：未通过行根因分类标签填写说明。
- `docs/RUNBOOK.md`：熔断口径（仅实现缺陷轮计数，契约/用例/环境轮 1 轮内转 verdict 不计数）、HITL 攒批签字（绑 commit 链）、spec 时间预算（≤ 1 轮会话，超时降级先做非契约面）、`trio-install.sh --check` 纳入日常自检。

### 第 4 步：切片 C（AC-12）
- `bin/trio-mutation-check.mjs` 按 §4.4 CLI：`bun bin/trio-mutation-check.mjs <diff-range> -- <test-cmd...>`；存活变异 → 退出码 1 + 存活清单；全杀 → 0；空 diff / 命令不存在 / 单变异超时 30s → 退出码 2 + 原因。
- `tests/` 补最小回归（小型 fixture diff 即可）。

### 第 5 步：真实验证（全部真实执行）
- 跑全部 `tests/*.test.mjs` 与 `bash bin/trio-selftest.sh`，全绿。
- 实证三个最小场景并贴输出：① `TRIO_ROLE=arch` 时 `cp /tmp/f src/x.py` 被拒（AC-1）② 经 symlink 写 `src` 被拒（AC-2）③ 基线 ≠ 待推 sha 时 pre-push 拒绝（AC-4）。
- 构造一份含 `[根因:实现]` 标签的样例报告跑 `bun bin/trio-check-report.mjs`，再跑一份缺标签的，贴两者退出码（AC-9）。

### 第 6 步：交付与看板
- 写 `docs/task/TASK-007-2026-10-29-门禁加固与流程落地/dev-<YYYYMMDD>-<HHMM>-release.md`（按 `templates/release.template.md`）：实现摘要 / Files Changed / AC-1..AC-13 实现情况 / 第 5 步真实输出粘贴。
