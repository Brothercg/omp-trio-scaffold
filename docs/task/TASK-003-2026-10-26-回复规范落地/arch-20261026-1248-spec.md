`## 5. 下一步任务分配块（回复结尾）`、`## 6. 挂起清单与集中补测`、`## 7. 修订流程`；
b) §2 表含字段名 `结论`、`状态`、`未完成项`、`产物`；
c) §3 表含字段名 `条目`、`期望 / 实际`、`复现`、`根因`、`解除条件 / 下一步`；
d) §5 含 `承接方` 与七段骨架名（逐字）：`【任务】`、`【必读】`、`【指令】`、
  `【交付】`、`【纪律】`、`【突出】`、`【完成】`；
e) §6 表含字段名 `条目`、`解除条件`、`触发者`、`解除后动作`；

g) 含语句 `user_signed` + 挂起清单清零 = 真闭环（逐字）；
h) 含优先级语句 `冲突时报告格式优先`；
i) 含轮次约定句 `-第<N>轮` 与目录命名形态 `TASK-<NNN>-<YYYY-MM-DD>-<slug>`。

### AC-5 T10 基本行为
**Given** 临时 fixture 报告（T1–T9 全合法，含反引号路径引用）与 fixture 文件树
**When** 运行 `bun bin/trio-check-report.mjs <报告>` **Then**：

  行号为 token 所在行、消息为 `引用路径不存在：docs/nope/missing.md`，退出码非 0。

### AC-6 T10 边界
**Given** 同一 fixture 机制 **When** 分别构造以下报告 **Then**：
a) token 含 glob 字符（`*` `?` `[`）→ 0 违例；
b) `tests/a.py::test_x` 与 `src/a.py:42` 按剥后缀后的 `tests/a.py` / `src/a.py` 校验
  （文件存在 → 0 违例；删除其一 → 恰 1 违例）；
c) 三反引号 fenced 块内出现不存在路径 → 0 违例；
d) 非反引号正文出现不存在路径 → 0 违例；
e) 裸文件名（无四前缀，如 `missing.md`）→ 0 违例；
f) 标点包裹 `（src/gone.py）` → 1 违例（剥标点后识别为 `src/gone.py`）。

## 3. 极值边界

- 空报告 / 仅表头报告：T10 产生 0 违例，不新增失败面（T1–T3 照旧拦）。
- 同一缺失路径在同一行多次出现：逐 token 逐条报违例。
- 大小写敏感（Linux 口径）；`Docs/` 等非小写前缀不识别（不校验）。
- 路径含空格的 span：token 分割后不构成完整路径，不校验——**已知限制**，
  REPLY-CONVENTIONS §4 呼吁避免路径含空格。
- Windows 反斜杠路径不支持（POSIX only）。

## 4. 错误契约

- T10 仅一种违例形态：`Violation(lineNo, "T10", "引用路径不存在：" + p)`；
  不改动 T1–T9 的任何消息与行号口径。
- 退出码沿用现有聚合语义：存在任何违例（T1–T10 任一）→ 非 0；全清 → 0。
- `--help` 与既有 CLI 参数行为不变（无新增参数）。

## 5. 非功能约束

- checker 保持单文件 bun 脚本、stdlib 依赖、只读。
- `docs/REPLY-CONVENTIONS.md` 单文件 Markdown，≤ 300 行。
- rules 追加块不破坏逐字节相等；不改任何既有行。
- 全部验收可离线重复执行。

## 1. 适用范围与优先级

## 2. 结论表（回复开头，先结论后细节）

每份角色回复 MUST 以结论表开头，之后才是解释性行文——**先讲结论，再简要阐述细节**。

| 字段 | 含义 |
|---|---|
| 结论 | 一句话：本步完成了什么 / 判定了什么 |
| 状态 | 看板态（`implementing` / `testing` / `qa_passed` / `blocked` / `waiting_user` / …） |
| 未完成项 | 有则逐条列（含失败 / 挂起），无则写「无」 |
| 产物 | 本步产出的完整相对路径（见 §4） |

目标：用户能在 5 秒内从任一角色回复读出「做完没有、卡在哪」。

## 3. 失败 / 未完成项解释

失败与未完成项逐条填下表（开发失败、测试失败、裁决挂起用同一套字段——
差异在内容，不在字段名）：

| 字段 | 含义 |

| 解除条件 / 下一步 | 谁做什么能转绿：挂起项填解除条件，缺陷填修复责任方 |

## 4. 路径规范

- 任务目录形态：`docs/task/TASK-<NNN>-<YYYY-MM-DD>-<slug>/`；产物引用 MUST 写
  从项目根起的完整相对路径（如
  `docs/task/TASK-003-2026-10-26-回复规范落地/arch-20261026-1248-spec.md`）；
  禁止裸文件名、禁止绝对路径与 `~`、禁止省略号缩写；路径避免含空格。
- 完整路径首次出现（可点击），后文可用短名指代。
- 轮次约定（身份不可变，轮次走自由段）：QA 复测报告主题必带 `-第<N>轮` 后缀
  （如 `qa-<…>-report-<主题>-第2轮.md`）；DEV 迭代交付带 `-第<N>轮`
  （如 `dev-<…>-release-第2轮.md`）；首轮可不带。
- qa 报告内的反引号路径由校验器 T10 机械核验存在性。

## 5. 下一步任务分配块（回复结尾）

任务未闭环时，回复 MUST 以「下一步任务分配」结尾：每个**当前可执行**步骤一段——
`**承接方：<角色>**` 行 + ` ```text ` 围栏完整提示词块（直接复制即用）。
提示词块必含七段（段名固定）：

【任务】TASK-00N-<slug> · <本轮目标>（第 N 轮）
【必读】<完整相对路径> —— <读它干嘛>
【指令】1. <动作，含改哪个文件的哪类内容 / 跑什么 / 裁决什么> 2. …
【交付】<产物落位与命名>（轮次后缀按 §4）
【纪律】<红线：不可越权路径、commit 显式 pathspec、…>
【突出】必须重启窗口 / 会话才能执行下一步（无则删本段）
【完成】<做到什么算完> + <回写 board 哪一段>

约束：

1. 看板状态 ≠ `user_signed` **或挂起清单非空**时 MUST 以分配块结尾；真闭环才写
   「任务闭环，无接力」。
2. **按需生成不预支**：只发当前可执行步骤的完整块，并行可执行才多块（各承接方
   一块）；后续步骤不预写（会失真），全局图景归 board「处置流程」段。
3. 同轮同步进 board 交接备注，board 为权威；冲突以 board 为准（会话重启后从
   board 重建接力）。
4. `blocked` / `waiting_user` 态「承接方」= `用户`，【指令】写明待裁决点。

## 6. 挂起清单与集中补测

挂起清单是 board 的结构化段（见 `templates/board.template.md` §7），字段：

| 字段 | 含义 |
|---|---|
| 条目 | AC 编号或操作名 |
| 解除条件 | 可判定的未来事实 |
| 触发者 | 条件成熟后谁负责跑补测 |
| 解除后动作 | 精确命令或步骤 |

规则：

1. 每轮回复合盘：未清零挂起项 MUST 出现在结论表「未完成项」。
2. 解除条件成熟 → 触发者下一轮一次跑完所有已成熟项（集中补测轮），结果进
   qa 报告 / 看板；不逐项零敲碎打。
3. `user_signed` + 挂起清单清零 = 真闭环。
