## 1. 分歧点

- **QA 主张（机械记录）**：按 AC-10b 字面执行「全仓 `*.md` 中 `docs/task/2026-10-26-` 为 0」，
  spec 自身命中 ×2、`dev-20261026-1346-release.md` 命中 ×2，字面口径不可达；
  未放宽口径，按契约缺口上报（B-2）。
- **DEV 主张**：机械执行需改 spec 正文两处，但 `arch-*.md` 归 ARCH 只读边界，DEV 无法自清；
  请 ARCH 裁决口径（限定文本除外 / 接受例外 / 放开 DEV 可清 dev-* 内副本）。

## 2. 判定

`契约缺陷`（表述欠限定，非实现缺陷、非误解）

## 3. 依据

1. AC-10b 用字面 `docs/task/2026-10-26-` 定义被检字符串，该定义文本本身必然含此字符串
   ——字面「全仓为 0」与「用该字符串写 AC」自相矛盾，机械口径不可判定。
2. `dev-*.md` 是历史执行记录，引用改名前后路径是合法证据（release 模板要求 Files Changed
   列真实路径），销毁证据换取字面 0 违背记录文本的用途。
3. 检查的真实意图是**导航类文本不得指向已改名目录**；记录类文本的定义与历史引用不在其列。

## 4. 处置

| 对象 | 动作 |
|---|---|
| 契约 `arch-*-spec.md` | 修订为 v4：AC-10b 加**记录类豁免**——`docs/task/*/arch-*.md`、`docs/task/*/dev-*.md`、`docs/task/*/qa-*.md`、`docs/task/*/board.md`、`docs/architecture/**` 豁免；豁免外任何命中即违例（已落） |
| 实现 `src/` | 无需改 |
| 测试 `tests/` | QA 按本裁决改 `tests/trio-reply-conventions.test.mjs` AC-10b：豁免类命中移出违例断言（可留信息性打印），断言「豁免外命中清单为空」；contract-gap 记录打印随口径落地删除 |

## 5. 后果

同类原则两条：① 断言口径向意图对齐，不为凑字面销毁合法记录；② AC 定义自身所引用的字符串时，
该定义载体（记录类文本）豁免于该字符串的清零检查。以后旧路径类检查一律按「豁免外为 0」表述。
