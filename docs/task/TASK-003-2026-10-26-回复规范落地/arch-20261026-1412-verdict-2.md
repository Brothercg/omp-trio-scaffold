## 1. 分歧点

- **QA 主张（机械记录）**：AC-1j 要求 `docs/REPLY-CONVENTIONS.md` 含字面 `标红`，
  但附录 A 逐字基准（cmp 实测 BYTE-EQUAL）用「红色」「红字渲染用 `\textcolor{red}{...}`」，
  字面 `标红` 无法落入基准而不破坏 BYTE-EQUAL；落地件已含红色渲染能力与「围栏外」语义，
  属契约表述内部矛盾，请 ARCH 定口径。

## 2. 判定

`契约缺陷`（断言口径未向逐字基准对齐；实现无缺陷）

## 3. 依据

1. 附录 A 是 DEV 逐字落位基准，BYTE-EQUAL 是已核准不变量（QA 报告实测一致）；
   断言要求基准中不存在的字面 token，等于强制二选一破坏交付件或断言失真。
2. 基准中 `红色` + `\textcolor{red` + `围栏外` 三标记已完整承载「标红」语义
   （渲染方式、渲染位置），语义无缺口——这是口径差，不是缺实现（QA 报告判定一致）。
3. 断言的对象是落位件；落位件与基准逐字绑定，故断言 MUST 对齐基准用词，而非反向改基准。

## 4. 处置

| 对象 | 动作 |
|---|---|
| 契约 `arch-*-spec.md` | 修订为 v4：AC-1j 改三标记口径——`红色`、`\textcolor{red` 与 `围栏外` 齐备（已落）；**附录 A 零改动**，`docs/REPLY-CONVENTIONS.md` 无需重落，BYTE-EQUAL 保持 |
| 实现 `src/` | 无需改 |
| 测试 `tests/` | QA 按本裁决改 `tests/trio-reply-conventions.test.mjs`：AC-1j 收紧为三标记断言（`红色`、`\textcolor{red`、`围栏外`，删去 `红色 \|\| 标红` 备选）；「AC-1j 追加：contract-gap 记录」用例（钉旧契约措辞的临时桥）删除 |

## 5. 后果

同类原则：断言口径向逐字基准对齐（改断言，不改基准）；断言 token 必须取自交付件实际用词。
桥接用例（记录契约缺口的临时检查）在裁决落盘后 MUST 删除，不得长期钉住已被修订的措辞。
