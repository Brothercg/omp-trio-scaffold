# TRIO 写策略 —— 单一真值源 (single source of truth)
#
# 本文件被两处同时消费，必须保持二者语义一致：
#   1. .omp/hooks/pre/trio-guard.ts   —— 进程内写前拦截（实时）
#   2. templates/pre-commit            —— 提交前兜底（git）
#
# ── 语法 ──────────────────────────────────────────────────────────────────
#   allow <role> <glob>       该角色允许写入该路径
#   deny  <role> <glob>       该角色禁止写入该路径
#   '#' 开头为注释；空白行忽略。
#
# ── 匹配语义 ──────────────────────────────────────────────────────────────
#   路径相对于项目根目录（POSIX 分隔符）。
#   '*' 匹配任意字符（含 '/'）；'**' 等价于 '*'。
#   例：'docs/task/*/arch-*.md' 匹配任意任务目录下以 arch- 开头的文件。
#       'requirements*.txt' 匹配 requirements.txt、requirements-dev.txt。
#
# ── 判定语义（deny 优先）──────────────────────────────────────────────────
#   1. 收集 role 匹配当前角色的全部规则（role 为 '*' 即适用于所有角色）。
#   2. 任一 deny 命中        → 拒绝。
#   3. 否则任一 allow 命中   → 允许。
#   4. 否则                  → 拒绝（fail-closed）。
#
#   角色取值：arch / dev / qa。
#   别名：pm → arch。hook 与 pre-commit 在匹配前会做归一化，
#         因此本文件只写 arch，无需重复写 pm 规则。
#   未设置 TRIO_ROLE 的会话不执行本策略（见 hook 与 pre-commit 的说明）。
#
# ── 作用域 ────────────────────────────────────────────────────────────────
#   本策略只管辖项目根目录以内的路径。xd:// 设备传输、local:// 会话草稿、
#   项目根目录以外的绝对路径不受管辖（它们不属于三方契约目录）。

# ─────────────────────────────────────────────────────────────────────────────

# ─────────────────────────────────────────────────────────────────────────────
# ARCH：系统架构师 / 技术仲裁者（别名 pm，由消费方归一化）
#   独占：docs/task/*/arch-*.md（契约、ADR 指针、裁决记录）
#         docs/architecture/**（跨任务的 ADR）
# ─────────────────────────────────────────────────────────────────────────────
allow arch docs/task/*/arch-*.md
allow arch docs/architecture/**

# 硬红线：契约发布者不得碰实现与测试（改这两处等于自己给自己判卷）
deny arch src/**
deny arch tests/**

# ─────────────────────────────────────────────────────────────────────────────
# DEV：高级软件开发工程师
#   独占：docs/task/*/dev-*.md（交付说明与验收清单）
#         src/**（业务实现）
# ─────────────────────────────────────────────────────────────────────────────
allow dev docs/task/*/dev-*.md
allow dev src/**

# 硬红线：不得修改测试（测试是 QA 与 ARCH 的契约载体）
deny dev tests/**

# ─────────────────────────────────────────────────────────────────────────────
# QA：对抗性质检与边界测试专家
#   独占：docs/task/*/qa-*.md（验收报告、缺陷文档、最小复现）
#         tests/**（测试用例与复现脚本）
# ─────────────────────────────────────────────────────────────────────────────
allow qa docs/task/*/qa-*.md
allow qa tests/**

# 硬红线：不得修改业务实现（发现缺陷只报告，修复是 DEV 的职责）
deny qa src/**

# ─────────────────────────────────────────────────────────────────────────────
# 门禁自身的保护：任何角色都不得改写门禁逻辑或策略
# （否则被约束者可以自行解除限制）
# ─────────────────────────────────────────────────────────────────────────────
deny * .omp/hooks/**
deny * .omp/trio/policy.txt
